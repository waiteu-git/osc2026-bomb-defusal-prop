# OSC2026 共通デザインルール(JLCPCB 2層・1.6mm・1oz)

決定日: 2026-09-29(ユーザー指示「デザインルールはJLCPCBでいけるように」「配線の太さも」)。
対象: 製作中の4基板(ワイヤー統合=`complicated_wires`、キーパッド+サイモン統合=`keypad`/`simon`、ボタン=`button`、タイマー兼ホスト=`timer`)。凍結中のモジュールには適用していない。

参照元: ユーザー提示の fab-wiki「JLCPCB用のKiCadデザインルール設定」と、JLCPCB公式の製造能力ページ(https://jlcpcb.com/capabilities/pcb-capabilities、2026-09-29に生HTMLを読んで確認)。**参照ページの数値はKiCad 7時代の設定画面の値**(ページの主内容であるKiCad 9の画像は、画像サーバーが応答せず読めなかった)。ページ作者自身も「製造能力が当時から変わった気がする」と書いているので、下表は「参照ページの値」と「公式ページの値」を突き合わせ、食い違いの理由を書いている。

## 使い方

```bash
python hardware/design_rules/apply_design_rules.py          # 各基板の .kicad_dru と .kicad_pro に適用
python hardware/design_rules/check_design_rules.py          # 検証(全ルールのプローブ試験、DRC、取付穴)
python hardware/design_rules/check_design_rules.py --parity # 回路図とPCBの差の参考表示も付ける
```

- **KiCadが開いているプロジェクトの `.kicad_pro` は書き換えない**(KiCadは保存時に、メモリ上の設定でファイルを上書きするため、外部からの編集は黙って消える)。その場合は `.kicad_dru` だけ書き、「KiCadを閉じて再実行」と表示する(ロックファイルが残っていて誤検出する場合は、KiCadが動いていないことを確認して `--force-pro`)。
- `.kicad_dru`(カスタムルール)はKiCadが保存で触らないので、KiCadを開いたままでも安全に反映できる。
- **Power / Power_Main のクラスとそのパターンはスクリプトの管理下**で、実行のたびに上書きされる(電源ネットを足すときは `apply_design_rules.py` の `NETS_*` に書く)。
- **基板(外形)をKiCadで動かした・作り直したら、`apply_design_rules.py` を再実行する**(四隅キープアウトの座標は、実行時に外形から読み取って書き込むため。動かしたまま再実行しないと、`check_design_rules.py` が「.kicad_dru が生成物と不一致」「キープアウトのルールが発火しない」で失敗する)。
- **新しいプロジェクトを作ったら**(例: キーパッド+サイモン統合基板)、`DEFAULT_PROJECTS` と `PROJECT_CFG` に名前を足して再実行する。ルールファイルはプロジェクト名で探されるため、フォルダを複製しただけでは効かない。button / keypad / simon は `panel: True` を設定済みで、PCBができた時点(再実行後)から四隅のキープアウトが生成される。

## 1. 基板の制約(「基板の設定 > 制約」、基板内の絶対的な下限)

参照ページの方針: 制約にはJLCPCBが追加料金なしで作れる下限を入れる。ビアとPTHは要求が別なので、アニュラー幅と最小ビア直径はビアに合わせる。

| 項目 | 設定 | JLCPCB公式(2026-09-29) | 補足 |
|---|---:|---|---|
| 最小クリアランス | 0.15 | 配線間0.10 / SMDパッド間0.15 | 実際に効くのはネットクラス(既定0.2)。JLCPCBが作れる0.15のパッド間隙でもネットクラスで引っかかる(既存フットプリントに該当なし。細かいSMD部品を使うときは要調整) |
| 最小配線幅 | 0.127 | 0.10(公差±20%) | 5mil。配線の既定は0.25 |
| 最小アニュラー幅(ビア) | 0.13 | ビアの環は0.05〜0.075 | 公式より厳しい(安全側) |
| 最小ビア直径 | 0.5 | 0.2/0.25穴は径0.45未満だと追加料金 | 穴0.3との組み合わせでDRCが通る最小のビアは0.56/0.3(公式より厳しい) |
| 最小スルーホール | 0.3 | 穴0.15〜(小さいと追加料金) | 参照ページの値 |
| 導体から穴のクリアランス | 0.33 | PTH〜配線 0.28(推奨0.35) | 参照ページの値 |
| 導体から基板端クリアランス | 0.3 | 外形ルーターで0.2(V-cutは0.4) | **単体の外形(ルーター切り出し)を前提**。面付けのV-cutにする場合は0.4。LED窓だけ例外(§3) |
| 穴から穴のクリアランス | **0.45** | PTH 0.45 / ビア 0.2 | 参照ページは0.5だが、Cherry MXホットスワップの実フットプリントが0.5に届かないため、公式の0.45に合わせた。**KiCadの既定は警告なので、エラーに引き上げた**(`rule_severities`) |
| 最小テキスト高さ / 太さ | 1.0 / 0.15 | 高さ1.0 / 線幅0.15 | シルクの文字のみ。図形の線(標準フットプリントは0.12mm)は検査できない(§4) |
| マイクロビア | 0.2 / 0.1 | — | 使わない |

Cherry MX(Kailh互換)ホットスワップのフットプリントの穴間隙は、ライブラリによって違う: kiswitch版(参照ブログが挙げるライブラリ)は**0.4398mm**(0.45に届かない)、daprice版(keyswitches.pretty)は**0.4889mm**。統合基板(キーパッド+サイモン)ではdaprice版を使うか、間隔を広げること(kiswitch版のままだと穴から穴のエラーになる)。

## 2. 配線の太さ(ネットクラス)

ネットクラスの配線幅・ビア径は**配線時の既定値**で、KiCadはDRCの下限としては強制しない(クリアランスだけ強制する)。下限は§3の `.kicad_dru` で強制している。

| 用途 | ネット | クラス | 既定の配線幅 | DRC下限 | クリアランス | ビア(径/穴) |
|---|---|---|---:|---:|---:|---|
| 信号(UART・I2C・GPIO・NeoPixelデータ) | 上記以外すべて | Default | 0.25 | 0.127 | 0.2 | 0.8 / 0.4 |
| 3.3V | `+3.3V` `+3V3` | Power | 0.5 | 0.3 | 0.2 | 0.8 / 0.4 |
| 5V(区画ごとの枝・TM1637の電源) | `+5V` `VCC_J*` `/VCC_J*` `TM_VDD` `/TM_VDD` | Power | 0.5 | 0.5 | 0.2 | 0.8 / 0.4 |
| **5V幹線(タイマー兼ホストのみ)** | `+5V`(timer) | Power_Main | 1.0 | 1.0 | 0.3 | 1.0 / 0.5 |
| GND | `GND` | Power | 0.5 | なし | 0.2 | 0.8 / 0.4 |

太さの根拠: IPC-2221の外層・1oz銅・温度上昇10℃で、必要な幅は 0.2A→0.033mm、0.6A→0.15mm、1.3A→0.43mm(式 I = 0.048·ΔT^0.44·A^0.725、A=断面積[mil²]。係数は計算サイトで確認、規格書本体は未確認。独立した再計算で一致)。逆に見ると、0.127mmの配線は約0.54A、0.5mmは約1.45A、1.0mmは約2.4A(いずれも10℃上昇)。**0.2Aだけが製造下限(0.127)に支配され、0.6Aでは0.15mm必要**。区画の電源枝(ポリスイッチ保持0.3A/トリップ0.6A)は余裕を見て0.5、1.3Aのタイマー幹線は約2.3倍の1.0にした。

- 電源ネットのクリアランスを0.2にしたのは、TO-92(ピン間隔1.27mm、パッド間隙0.22mm)の隣に電源ピンが来ても違反にならないようにするため(JLCPCB公式の下限は0.10)。
- GNDは主にベタで引く前提で、配線幅の下限は設けていない(短いスタブまで縛らないため)。ただし**ベタが本当にあるかはDRCでは見ていない**(タイマーの1.3A戻り電流もここに乗る)。PCBに配線・GNDベタを作る段階で確認すること。
- ネットクラスのパターンは大文字小文字を区別する。`.kicad_dru` の名前判定(`A.NetName == ...`)は区別しない。PCBのネット名はスクリプト生成PCB(`+3V3`、`VCC_J1`)と「回路図から更新」(`+3.3V`、`/VCC_J1`)で表記が違うので、両方の表記を登録してある。

## 3. カスタムルール(`<名前>.kicad_dru`)

| ルール名 | 内容 | 対象 |
|---|---|---|
| `osc_3v3_min_track_0p3` | 3.3Vの配線は0.3mm以上 | 全基板 |
| `osc_power_min_track_0p5` | 5V系の配線は0.5mm以上 | 全基板 |
| `osc_main_rail_min_track_1p0` | `+5V`は1.0mm以上 | timerのみ |
| `osc_pth_min_ring_0p18` | めっき穴パッドの環は0.18mm以上(JLCPCB絶対下限。見出しは0.20、推奨0.25) | 全基板 |
| `osc_pth_min_drill_0p5` | めっき穴パッドのドリルは0.5mm以上(JLCPCB推奨) | 全基板 |
| `osc_npth_min_drill_0p5` | 非めっき穴は0.5mm以上(JLCPCBの下限。非めっきスロットの1.0mm以上は未検査) | 全基板 |
| `osc_led_window_edge` | SK6812MINI-Eのパッドの基板端クリアランスを0.2mmに緩和(参照記号はPCBから自動で拾う: D1〜D20) | complicated_wiresのみ |
| `osc_corner_keepout_*` | 80×80パネルの四隅12mm角に、パッド・ビア・配線の端点・部品原点を置かない(取付穴は除く)。PCBの外形から原点を自動検出 | PCBがある基板(button/keypad/simonはPCB作成後) |

**LED1の四隅キープアウト例外(complicated_wiresのみ、2026-09-29、複雑ワイヤ担当がユーザー判断として連絡)**: 原作の状態LEDは右上の角ぴったり(幅約87%・高さ約10%)にあり、現在のLED1の位置(パネル座標約(76.5, 3.7))は原作に一致する。取付穴H2は(71, 9)で、LED1中心まで約7.6mm。LED外形(半径約2.9mm)とネジ頭(半径約2.5mm)を引いても約2.2mmの余裕があり、実物では干渉しない。簡易判定(パッド中心・部品原点が角に入るか)が実際の衝突ではないところを検出しているため、LED1を除外した: パッドと部品原点は参照記号で、**配線とビアはLED1の部品領域(courtyard)との重なりで**除外する(LED1へ配線するとき、端点が角に入って再び違反になるのを防ぐ)。他の部品は従来どおり検出される(R14を角に移した試験で確認)。ネジ頭や筐体の寸法が変わった場合は再確認すること。

**状態LEDの四隅キープアウト例外を全基板に拡大(2026-10-01、ユーザー決定をボタン担当が連絡)**: 状態LED(緑)はどのモジュールでも右上の角付近に置くことになるため、各基板の状態LEDだけを恒久的に四隅キープアウトの対象外にした。対象はプロジェクトごとの参照記号: button=LED9、complicated_wires=LED1(上記)、four_button=D5(現在位置(52,6)は角の外だが、標準位置(60,6)付近へ寄せても違反にならないよう先に許可)。判定は上記LED1と同じ(パッドと部品原点は参照記号、配線とビアは部品領域との重なり)で、他の部品は従来どおり検出される(プローブ試験で確認)。理由と幾何(ボタン基板、幾何だけの見積り・実物は未確認): LED9の中心から取付穴H2まで約8.2mm、LED半径約1.75mmとネジ頭半径約2.5mmを引いても約3.9mmの余裕。complicated_wiresは約7.6mm・余裕約2.2mm。**ネジ頭やケースの寸法が変わったら、全基板で再確認する**。設定は `apply_design_rules.py` の `PROJECT_CFG[...]["corner_exceptions"]`。keypadとsimon(PCBなし・four_buttonに統合)は対象外。timerには状態LEDがない。

`osc_led_window_edge` の理由: SK6812MINI-E(逆実装)のフットプリントは、自身のEdge.Cutsで光の窓を持ち、パッドまで最短0.2467mm。これは0.3mmにも0.5mmにも満たない(DRCの表示は1パッドあたり1項目だけなので、GUIの0.35mmは本当の最小ではない)。JLCPCB公式の下限0.2mmには収まるので、この窓のパッドだけ例外にした。ただし余白は0.047mmしかなく、JLCPCBの外形ルーター公差は±0.2mm(§7)。

## 4. DRCで検査できないこと・限界

- 「UARTの下面にGNDの途切れないベタを敷く」ルール、GNDベタの有無は検査できない(配線・ベタ作成時に目視)。
- 四隅のキープアウトは**基準点だけ**を検査する(パッド・ビアの中心、配線の端点、部品の原点)。次は検出できない: 両端が角の外にある配線が角を横切る場合、原点とパッド中心が外にある部品の本体が角に食い込む場合、角の銅ベタ。厳密に見るなら、KiCadのルールエリア(キープアウトゾーン)を四隅に描く(未試験)。めっき穴付きの取付穴フットプリント(`MountingHole:*_Pad`)を使うと、そのパッドは除外されずに検出される(現在の4穴は非めっきなので問題なし)。
- シルクの図形の線幅(JLCPCB最小0.15mm)、パッドからシルクまでの距離(0.15mm。JLCPCBはパッド上のシルクを自動で削る)、同一ネット間の配線間隔(公式ページに0.25mmとの記載あり)は検査していない。標準フットプリントのシルク線は0.12mmで、JLCPCBの最小0.15mmを下回る(印刷は可能だが細い)。新規のシルクの既定は0.15mmにしてある。
- KiCad 10.0.3の`kicad-cli`は、`.kicad_dru`の文法エラーを**黙って無視**する(終了コード0)。`check_design_rules.py`は、ルールごとに違反を1つずつ入れた一時PCBを作り、**全ルールが発火するか**を確認する(これが実質の文法チェック)。`.kicad_dru`はBOMなしUTF-8で、コメントは行頭の`#`のみ、`matches`(正規表現)は使えない。
- `check_design_rules.py` は、エラー相当の違反が1件でもあると失敗にする。警告(ライブラリ差・シルク重なり・文字高さ)は件数のみ表示。回路図との差(パリティ)は `--parity` で参考表示する。

## 6. 適用の記録

- 2026-09-29: 5基板すべてに `.kicad_pro` と `.kicad_dru` を適用済み(タイマーとワイヤー統合は、ユーザーがKiCadを閉じたあとに適用)。`check_design_rules.py`で全ルールの発火・取付穴H1〜H4(NPTH、ドリル2.6、縁から9mm)を確認済み。button / keypad / simon はPCBがないため、`.kicad_dru`の文法はtimer・complicated_wiresで検証した同じ生成器の部分集合として担保している。
- 検証: 4つの独立した検証(数値の再確認、ルールの挙動、スクリプトの安全性、抜け漏れ)を実施し、その指摘を反映した(NPTHドリルのルール追加、穴間隔のエラー化、LED窓の参照記号の自動取得、LED1例外を配線・ビアにも適用、TO-92の対処の訂正、プローブ試験の全ルール化など)。

## 7. JLCPCB発注時のチェックリスト(DRC外)

- 板厚1.6mm、銅箔1oz、2層。表面処理(HASL鉛フリー/ENIG等)はPCBファイル上は未指定で、注文フォームで選ぶ(未決)。
- 外形は単体のルーター切り出しを前提(V-cutにするなら銅箔から端まで0.4mm)。全基板80×80mm。
- **ソルダーレジストブリッジ**: SK6812MINI-Eのパッド間隙は0.15mm。公式の製造能力ページはブリッジ0.10mmと書くが、注文ガイドには「パッド間隔0.2mm以上でブリッジを作れる、注文時に指定」との記載があると、検証担当が報告している(ハブは未再確認)。0.15mmではブリッジが省かれる可能性がある(手はんだなら影響は小さい)。
- **LED窓(SK6812MINI-E、内角R0.5のドッグボーン)**: パッドまで0.2467mmで、公式ルーター公差±0.2mmに対して余白0.047mm。ルーターの刃径・内角の許容も未確認なので、初回発注前にJLCPCBの問い合わせかDFM表示で確認する。
- 非めっき穴(取付穴Ø2.6mm)は、ガーバー出力で非めっきのドリルファイル(-NPTH.drl)に分かれる。
- 同一ネット間の配線間隔0.25mm(公式ページの記載、意図は不明)は、配線後に目視で確認。
