## 4. 既知のリスクと、過去に自分が訂正した誤り

### 既知のリスク

1. **TM1637のVDDがデータシートの保証外**: 3.3V駆動は保証範囲(4.5〜5.5V)外で、暗い・不安定の可能性がある。5V駆動+Pico直結はHigh(3.3V)がしきい値(0.7×5V=3.5V)未満で保証外。実測A〜Dで決める。
2. **A-551SRDの輝度**: 代表値10mcd@10mA(最小4mcd)。3.3V駆動だと更に暗い可能性。保険はOSL40391-IRA。採用する場合は記号・フットプリント・配置の作り直しが要る(16ピン、うち3ピンNC)。
3. **セグメント電流が未測定**: 上記のとおり。全点灯・輝度最大の消費電流を、USBパワーメーターで実測する。
4. ~~Pico 2の3V3(OUT)の許容電流が未確認~~ → **確認済み(2026-09-27)**: Raspberry Pi Pico 2 Datasheet(RP-008299-DS-3)§3.1 pinout(印刷ページ9)に、3V3で外部回路に給電できること、最大出力電流はRP2350の負荷とVSYS電圧に依存すること、負荷は300mA未満が推奨、と書かれている(推奨で保証値ではない)。ハブの確認と一致。TM1637側の負荷(平均約75mA・ピーク約150mA、推定)は範囲内の見込みだが、RP2350自身の負荷との合計は実測で確認する。出典URLは`timer_design_notes.md` §3-3。
5. **実機未確認**: 回路もスクリプトも実機では動かしていない。ブレッドボードにA-551SRD(段間15.24mm)が挿さるかも現物で未確認。
6. ~~ERC 4件が残っている~~ → **解消(2026-09-27)**: PWR_FLAGを4ネット(GND/+5V/+3V3/TM_VDD)に置き、エラー4件は0件、警告1件(U1 pin38とPWR_FLAGの`pin_to_pin`、他モジュールと同じ既知の無害なもの)のみ。以前の試行が失敗した原因は、lib_symbolsキャッシュの記号名が`PWR_FLAG`のままで`power:PWR_FLAG`になっていなかったこと(当時は`unit`/`body_style`の問題と見ていたが誤診)。
7. **PCBは配置のみ**: 外形・取付穴・配線・GNDベタは機構情報の確定後でないと作れない。日程を圧迫する要因。
8. ~~netlist照合は私だけ~~ → ハブが2026-09-27にA-551SRD版を検算済み(ピン配置・ネットとも意図どおり)。C3・PWR_FLAG追加後は、変更前後のネットリスト差分(C3が+5VとGNDに加わっただけ)を私が確認した。

### 過去に自分が訂正した誤り

1. **極性の誤り**: 「C-801SR(カソードコモン)はTM1637に直結で使える」と説明したが、データシートでコモンアノード専用と確認して訂正し、A-801SR、のちにA-551SRDに変更した。
2. **「Picoの記号にバグがある」との誤判断**(2026-09-16頃): osc-09の反論で撤回。原因は自作シンボルのY符号の取り違え(正しくは配置Y−ローカルY)で、修正済み。ハブ連絡事項に記載されている。
3. **検証ワークフローの誤検出への対応**(2026-09-17): 「GPIO番号ズレ」「GRID-COM未配線」「SEG順序逆」などの報告を、ネットリストの実データで反証した(私の誤りではないが、対応として記録)。
4. **PCBの寸法・配置の誤り**(2026-09-24): Picoのパッドを回路図のシンボル寸法(±17.78mm)のまま置いていた(実物のピン列は中心から±8.89mm)。またLEDのコートヤード重なり(6mm間隔→10mm)、TM1637/J1の基板端への近さを修正した。
5. **3.3V駆動の整理不足**: 2026-09-15に「3V3(OUT)から給電」と決めた時点では、データシートの保証範囲との関係を整理していなかった。2026-09-24に整理し直し、実測で決める方針に改めた。
6. **kicad-cliの出力判定**: Windowsで出力が文字化けするため、文字列判定で誤ってOKとした。戻り値(3=読み込み失敗、5=違反あり)で判定するように変更した。

1. **基板の製法**(発注PCB/ユニバーサル基板)とその決定期限。決まらないとPCB作業の要否が決まらない。
2. **機構情報の期限**(取付穴の中心・外形・JST辺・案A/B)。10/3頃までに来れば間に合う見込み。
3. **試験部品の注文**(約¥600、共通)とOSL40391-IRA保険(¥200)のユーザーへの提案。
4. **UARTプロトコル**: タイマーが受け取るデータ(残り時間、ストライク数など)の定義をソフト担当と詰める(ハブが申し送りにまとめると回答済み)。
5. ~~電流の扱い~~ → ハブ回答: 5V入力に100µFのバルクを追加(C3、実施済み)。「200mA=平均」は暫定で、ユーザーの最終確認待ち。
6. ~~ERC 4件の許容かPWR_FLAGか~~ → ハブ回答: PWR_FLAGで0件に(実施済み、警告1件のみ)。
7. ~~A-551SRD版ネットリストの再検算~~ → ハブが検算済み、再検算は不要。

(1)〜(3)の製法・期限・試験部品・OSL保険は、ハブがユーザー判断の項目としてまとめる。
