## 1. 実物の外観・ルール(一次情報)

### 1-1. 外観(KTANE Wiki + 実機画像)
- モジュールは4枚の「パネル」(ページ)を持ち、UP/DOWNボタンで切り替える。同時に見えるのは1ページのみ。
- 各パネルには1〜3本のワイヤーがあり(全く無いパネルも5%の確率で存在)、パネル内で左側に番号(実機画像では2枚目パネルの例で「4,5,6」)、右側に接続先の文字 **A/B/C** が縦に並ぶ。ワイヤーは左の番号から右のA/B/Cのいずれかへ弧を描いて繋がっている。
- 画面右下あたりに小さな「ステージインジケーター」(進捗を示すランプ)があり、DOWNボタンを押してページを進めるたびに1つ点灯する(UPで戻ってもランプは消えない=既に合格したページの記録として残る)。
- ワイヤーの色は **赤・青・黒** の3色のみ(単色。複雑ワイヤのような縞模様は無い)。
- 出典: [KTANE Wiki: Wire Sequence](https://ktane.fandom.com/wiki/Wire_Sequence)、公式マニュアル14ページ(`bombmanual.com/ja` で確認、タイトル「モジュール詳細：順番ワイヤ」)。
- 攻略ブログ(xanmark2.wordpress.com)は5部構成(Part1〜5)。**Part4に「複数パネル配線(日本語マニュアル14ページ)」の節があり、これが本モジュール(順番ワイヤ)の解説**である: パネルが4枚で右のランプが現在のパネルを示す、各パネルに接続口が3組(最大12本)、色の数は全パネルで通算する(例: パネル1の赤3本+パネル2の1番目の赤=赤の4回目)、赤・青・黒を別々に数える、という内容で、Wikiと公式マニュアルの記述と一致する。同じPart4の「ナンバーメモリー」は別モジュール(数字メモリー)。複雑ワイヤはPart2(複雑な配線)。(前回までのメモは「複数パネル配線=複雑ワイヤ」「Wire Sequenceの解説は見当たらない」と誤って書いていた。独立監査で発覚し、2026-09-24に訂正した。)

**ストライク/解除条件**
- 間違った接続先のワイヤーを切る → ストライク。
- 必要なワイヤーを切り終える前にDOWNを押す → ストライク、かつ次のパネルには進まない(現在のパネルに留まる)。
- 最後のパネルで必要なワイヤーを全て切ってからDOWNを押す → 解除。
- UPで前のパネルへは戻れる(確認用)が、ステージインジケーターは戻らない。DOWNを押すまで確定しない。

## 2. 新方針(2026-09-24機能会議)の反映

ジャンパー線の抜き差しではなく、**実際にワイヤーを切る**。切ったワイヤーは**端子台(ターミナルブロック)**で交換して繰り返し遊べるようにし、**各ワイヤーと基板の接続部にNeoPixelを置いて色を示す**。

### 重要な気づき: ワイヤーの「色」はNeoPixelが決める、物理的なワイヤー自体の色は関係ない
GPIOで読めるのは「繋がっているか/切れているか」だけで、物理的なワイヤーの被覆色をマイコンが検知する手段は無い。したがって:
- **採用: NeoPixelがそのラウンドの「論理的な色(赤/青/黒)」を表示し、物理ワイヤーは色を問わない汎用の1色(またはあり合わせの色)でよい。** ラウンド開始時にファームウェアが各位置の色をランダムに決めてNeoPixelを光らせるだけで、毎回完全にランダムな並びを作れる(スタッフが「表示された色に合う色のワイヤーを用意する」手間が要らない)。
- 代替案(不採用): 物理ワイヤー自体を赤/青/黒の3色で用意し、NeoPixelは色の「確認表示」として同じ色を光らせるだけにする。写真映えは上がるが、スタッフがラウンドごとに正しい色のワイヤーを正しい位置に手動で選んで挿す必要があり、ランダム性がスタッフの手作業に依存してしまう(操作ミスで色が食い違うリスクもある)。今回は再現度よりも「毎回勝手にランダムな並びになる」再遊性を優先し、不採用とした。
- ワイヤー本体の購入は、この結論により**色の使い分けが不要**になったため、姉妹モジュール(ワイヤー・複雑ワイヤ)と共同購入する多色パックのうち余った色を回すだけで足りる(後述4章)。

### 「ページ切り替え」の表現方法比較

| 案 | 内容 | 再現度 | 実現可能性 | 判定 |
|---|---|---|---|---|
| **A(採用)** | 4ページ分のワイヤーを**常時全て見える状態**で配置(実機は最大12本だが、80mm角に収めるため**4ページ×2本=8本**に縮小、5章)。4個の「グループ(ページ)」に区切って表示。UP/DOWNボタンは残し、DOWNで「現在アクティブなグループ」を確定・判定して次のグループへ進む(実機のページ送りと同じ操作感)。ステージインジケーターLED(4個)で進捗を表示。未確定の後続グループのワイヤーは切っても即座には判定されない(仕様は3章参照)。**実機は1ページずつしか表示されない(公式マニュアル14ページ)ので、全ページ常時表示は実機からの意図的な逸脱**。 | 高(ワイヤー・A/B/C・UP/DOWN・ステージランプが全て実在) | 80mm角(ユーザー指示で確定検討)に8本で収まる(5章の配置図参照) | **主案** |
| B | 物理的にワイヤーを隠す/入れ替える機構(サーボ式カバー、回転式パネル等)でページごとに別の3本を見せる | 最高 | 低い。機構が複雑・可動部が壊れやすく、3週間の納期でリスクが高い。KTANEの「切ったワイヤーがそのまま残る」達成感も失われる | 不採用 |
| C | 物理ワイヤーは3本(1ページ分)だけ用意し、小型OLEDに現在のページ番号とA/B/C対応を表示、DOWNで次ページのデータに論理的に差し替える | 部品点数最小・80mm角でも余裕 | 実現は容易 | 物理ワイヤーを実際に切っていく体験(切ったワイヤーが残る達成感)が失われ、実質OLED表示モジュールになってしまう。見た目の再現度優先の方針に反するため不採用(なお実機自体は1ページずつしか表示しないので、不採用の理由は「全ページが並ぶ再現度」ではなく、この体験の喪失) |

→ **案Aを採用**。ワイヤー本数は、パネルが80mm角になる前提で8本(4ページ×2本)とする(5章)。実機の最大12本には及ばないが、4ページ・累積カウントというゲームの骨格は保つ。

## 3. 動作仕様(ファームウェア側の前提、ハード設計に影響する部分のみ)

- **ラウンド開始(ホストからのリセット/開始コマンド受信時)**: まずその時点の全ワイヤーGPIO状態を1回スキャンし、LOW(導通=ワイヤーが挿してある)の位置だけを「今回のラウンドで判定対象の位置」として記録する。HIGH(未導通)だった位置は「そもそも空パネルのワイヤーなし位置」として永久にスキップする。その後、記録した各位置にランダムに色(赤/青/黒)を割り当ててNeoPixelを点灯させる。
  - これにより「空きスロットの検出」に追加ハードウェアは不要(スロットは8本固定配線だが、毎回何本使うかは自由)。
- **判定**: 出現回数は、赤・青・黒の色ごとに、**ページ1から通算して**数える(1章の表の「通算出現回数」。数える順は「ページ1→4、同一ページ内は上から下」)。ラウンド開始時のスキャンで導通していた位置は全て数える(既に切ったワイヤーも数に含め、ページごとにカウンタをリセットしない)。DOWNボタン押下時に、アクティブなグループの全該当位置が正しく切断されていれば次のグループへ、そうでなければストライク(現在のグループに留まる)。
- **ストライク演出**: 該当グループのNeoPixelを短時間赤く高速点滅させ、UART経由でホストへストライクを通知する(モジュールはホストへ通知するだけで、ストライク回数はホストが管理してタイマー表示ユニットへ渡す。爆弾解除モジュール案.typの「モジュールは状態のみ通知」の方針で、モールスコードモジュールと同じパターン、`morse_code_design_notes.md`参照)。本モジュール自身はストライク回数を保持しない。
- **解除演出**: 最終グループも正しく通過したら、状態表示LED(緑、共通仕様)を点灯。加えて全NeoPixelを一瞬白くフラッシュ→消灯、等の演出はファームウェア側の任意(ハードウェア追加は不要)。
- 接続先A/B/Cは各ワイヤー位置ごとに**固定**(実機同様、プレイヤーが選べるのは「切るか切らないか」だけ)。物理的な行き先端子は用意せず、シルク印刷でA/B/Cのラベルをそのワイヤーの隣に印字するだけでよい(複数の行き先端子へ実際に配線を選択させる必要はない)。

### 5-5. リスクと、収まらなかった場合の代替案
- **切断作業のしやすさが最大のリスク**: 行ピッチ8.5mmで通路は6.5mm。ニッパーの先端は入るが余裕は小さいので、ワイヤー中央部の仕切り板は低くする(または切り欠く)。実物での作業性確認が必須(ハブ依頼: サンプル実測時にあわせて確認)。
- **基板の作り方が未決定**(ハブ確認): (a) チップは実質発注PCB前提(コスト最小、ただし10月上旬の納期に日程リスク)、(b) 手配線ならAE-WS2812Bモジュールに戻す(BOM+¥360+ダイオード、日程リスク小)。ただし(b)のAE-WS2812Bは3.3V直結が規格外で、ダイオード降圧(または追加のレベルシフタ)が前提になる。サンプル実測後に決める流れで、それまで両方のBOMを併記する。
- **WJ141V(プッシュ式、ワイヤーモジュールが採用決定)を選んだ場合の再評価**(縦挿し=電線は上から挿すと仮定): 端子台は極列方向7.62mm×奥行き12.8mm、高さ13.8mm。
  - 「1端子台/端」(1極のみ使用)のままだと、極列方向7.62mmを行方向に向けると行ピッチが最低7.62+仕切り板2=9.6mmとなり、8行で約77mm+外壁で80mm近くになり、8本は収まらない(6本なら約60mmで収まる)。
  - **ワイヤーモジュール担当の方式(2本のワイヤーで1つの2極ブロックを共有し、電線が上に出てから広がる)を使えば収まる可能性が高い**: 2行分(2×8.5=17mm)の幅に、ブロックの極列方向7.62mmが入る。ブロックの奥行き12.8mmはワイヤー方向に向く。電線は上から挿すので、ブロックの穴の位置間隔(ワイヤーの見える弧の長さ)と、ブロック同士の隙間を分けて考えられ、端の合計は、(a)チップなら 5.4+1+12.8+隙間約7+12.8=約39mm(+外壁4mmで約43mm)、(b)モジュールなら 11+1+12.8+隙間約7+12.8=約44.6mm(+外壁4mmで約48.6mm、中央帯50mmに対して余裕は約1.4mmでほぼ無い)と概算できる。端子台は8個(各端4個)で¥320。
  - ただし、ワイヤーが上に立ち上がるので仕切り板の高さは端子台の13.8mm以上が必要で、切断作業性・ワイヤーの弧の高さも含め、実物を並べて確認するまで結論は出せない。挿入方向は商品写真からの推定で、ワイヤーモジュール担当のサンプル実測(取り外し方法・挿入方向・保持力)の結果を待つ。
- **代替案(a): 6本(3ページ×2本)に削減**: 行ピッチを10mmに広げて切断作業性を上げる(高さ約62mm)。ゲームの骨格は保てるが、ページが3つになる。
- **代替案(b): 2列×4行に変更(NeoPixelが(a)チップの場合のみ)**: 2列×4行(1列あたり幅約37mm、ワイヤー可視長14mm、2列で約74mm)が、中央の横帯(y=15〜65、幅80mm)に収まる。行ピッチも11mmに広がり切断作業性が上がる(高さ約46mm)。ただし可視ワイヤー長が短くなる。(b)のモジュール(11mm)では1列が約42mm+外壁で、2列だと約85mmになり80mm角に収まらない。

## 7. 回路概要(ブロック図、詳細配線はKiCad化時に確定)

```
                              +-------------------+
  JST XH 4極                  |     Pico 2 (U1)   |
   Pin1(TX) <----------------- GPIO0  (UART0 TX)  |
   Pin2(RX) -----------------> GPIO1  (UART0 RX)  |
   Pin3(VCC 5V) -- VSYS / NeoPixel VDD             |
   Pin4(GND)    -- 共通GND                          |
                              |                   |
  ワイヤー W1〜W8 (端子台x16、ジェネリック2極)      |
   信号極 --[1k]----+-------- GPIO2〜9             |
                    +--[10k]-- 3V3 (外付けプルアップ)
   GND極  ----------(共通GND)                      |
                              |                   |
  NeoPixel WS2812B(V5) x8 デイジーチェーン         |
   DIN(W1) <--[330R]---------- GPIO10              |
   DOUT→DIN→…→W8                                  |
   VDD: +5V --[R23 0R / D10 1N4007]-- NEO_VDD        |
   VDD-VSS間: 各0.1uF、チェーン先頭に100uF電解      |
                              |                   |
  ステージLEDx4 --[330R]-----  GPIO11〜14          |
  UP  ボタン ---------------  GPIO15 (内部PU)      |
  DOWNボタン ---------------  GPIO16 (内部PU)      |
  状態LED(緑) --[47R]-------  GPIO17               |
                              +-------------------+
```

- **NeoPixelのDIN入力電圧(2026-09-24、複数回訂正)**: Pico 2のGPIO出力は3.3Vで、NeoPixelのVDDは5V。DINのHigh判定(VIH)は部品の版で違う。(1)ワイヤーモジュール担当は当初「VIH=0.7×VDD(5Vで3.5V)」と共有し、(2)ハブがWorld Semi WS2812B V5の実データシート(hardware/maze/datasheet/WS2812B_20200225.pdf 2ページ)を直読して「VIH min=2.7V(VDD=5V条件)、VIL max=0.7V」と確認し、私も同じPDFで確認した。(3)さらに複雑ワイヤ担当が、**2021年以降の「WS2812B-V5/W」文書ではVIH=0.63×VDD(5.0Vで3.15V、3.3Vに対する余裕0.15V)**であること、AE-WS2812B(単体モジュール)は旧版(VIH=0.7×VDD)で3.3V直結は規格外であることを指摘した。
  - したがって(a) WS2812B(V5)チップは、**届いた個体の版と、実際のVDD(5Vレールからポリスイッチ・配線で落ちた値)を実測**して確認する(動作確認手順6章)。
  - **保険として、回路図にNeoPixelのVDDの選択ランドを入れた**: +5V →(R23=0Ωリンク、既定)または(D10=1N4007)→ NEO_VDD。3.3V直結のマージンが足りなければ、D10を実装してR23を外し、VDDを約4.3Vに下げる(VIH=0.63×4.3≒2.7V、0.7×4.3≒3.0V)。NeoPixelのVDD下限(V5チップ3.7V、AE-WS2812Bモジュール3.5V)を割らないことを、VDDを測って確認する。ワイヤーモジュール担当も同様のランド(R15)を入れている。
  - (b) AE-WS2812Bモジュールは、最初からD10実装(またはレベルシフタSN74AHCT125N等、価格未確認)が前提。
  - 電源はJSTのPin3(5V、ポリスイッチ後)から供給する。
- **ワイヤー切断検知の保護と構成(ワイヤーモジュール担当の確定値に統一)**: ワイヤー端子は露出しており来場者が触れるため、信号側に直列1kΩ(ESD・短絡時の電流制限)を入れ、GPIO側に外付け10kΩ→3V3のプルアップを付ける(内蔵プルアップは使わない)。導通時のGPIO電圧は3.3V×1k/(10k+1k)=0.3V(VIL上限0.8V)、切断時は3.3V。ソフトウェアのデバウンス(数十〜100ms)も併用する。GND極は基板上の共通GNDネットにまとめる。UP/DOWNボタンだけは内部プルアップを使う。
- ピーク電流: NeoPixel8灯(+ステージLED4灯は単純LEDで別枠)は共通仕様の「輝度をファームで制限して200mA以内」の方針に従う。迷路モジュールの実測値(MAX_BRIGHTNESS=20で3灯点灯時108mA)を参考に、同程度のMAX_BRIGHTNESS上限をファームで設定する前提とする(詳細は回路図確定時に再確認)。

## 8. KiCad回路図(作成・検証済み)

`hardware/wire_sequence/wire_sequence.kicad_sch`(+ `wire_sequence.kicad_pro`)。生成スクリプト `gen_wire_sequence_sch.py`(と補助の `kilib.py`)で機械的に作成した(参考実装 `hardware/keypad/keypad.kicad_sch` と同じ、U1=`(at 149.86 76.2 0)`)。配置・配線の規則は、過去の落とし穴に沿っている: 座標は全て1.27mmの整数倍、ワイヤーは2点のみ、lib_symbolsのサブユニット名に「Library:」を付けない、ライブラリのピンの絶対座標は `(配置X+ローカルX, 配置Y−ローカルY)`(Yは引き算)。全部品を回転0で置き、ピン同士を「ネット名のラベル」でつなぐ(ピンごとに5.08mmの短い線+ラベル/電源シンボル)方式なので、長い配線の交差が無い。

### 部品(参照子)
| 参照子 | 部品 | 役割 |
|---|---|---|
| U1 | Pico 2(`RPi_Pico:Pico`) | MCU。JSTの+5VをVSYS(pin39)へ。VBUSは開放 |
| J1 | JST XH 4極 | ホスト接続。Pin1=UART_TX(GPIO0)、Pin2=UART_RX(GPIO1)、Pin3=+5V、Pin4=GND |
| TB1〜TB8 | ジェネリック2極コネクタ | ワイヤーW1〜W8。Pin1=信号側、Pin2=GND側(**端子台の型番・個数・共有方式は未確定**なので、1本の両端を1個のコネクタとして抽象化) |
| R1〜R8 | 1kΩ | 信号側の直列抵抗(W*_T → W*_IN) |
| R9〜R16 | 10kΩ | 外付けプルアップ(+3V3 → W*_IN) |
| NP1〜NP8 | WS2812B(`LED:WS2812B`) | NeoPixel。DIN→DOUTのチェーン(W1..W8の順)。フットプリントは基板の作り方の決定まで未定 |
| R17 | 330Ω | NeoPixelデータ線の直列抵抗(GPIO10 → NEO_DIN) |
| C1〜C8 / C9 | 0.1µF / 100µF電解 | NeoPixel電源のバイパス / チェーン先頭の電解 |
| R23 / D10 | 0Ω / 1N4007 | +5V → NEO_VDD の選択ランド(既定はR23=0Ω。D10は不合格時に実装) |
| R18〜R21 + LED1〜LED4 | 330Ω + 5mm LED | ステージインジケーター4灯(GPIO11〜14) |

| SW1 / SW2 | タクトスイッチ(1273HIM-160G-G、12mm角、フットプリントSW_PUSH-12mm) | UP(GPIO15) / DOWN(GPIO16) |

### ピン割当(Pico 2、ネットリストで確認済み)
GPIO0=UART_TX(J1.1)、GPIO1=UART_RX(J1.2)、GPIO2〜9=W1_IN〜W8_IN(物理ピン4,5,6,7,9,10,11,12)、GPIO10=NEO_RAW(R17経由でNP1.DIN、物理ピン14)、GPIO11〜13=STAGE1〜3(物理ピン15,16,17)、GPIO14=STAGE4(物理ピン19)、GPIO15=BTN_UP(物理ピン20)、GPIO16=BTN_DOWN(物理ピン21)、GPIO17=STATUS(物理ピン22)。3V3(物理ピン36)=プルアップ電源、VSYS(物理ピン39)=+5V、GND=物理ピン3,8,13,18,23,28,33(AGND),38,42。未使用のGPIO18〜22・26〜28、RUN、ADC_VREF、3V3_EN、VBUS、SWCLK/SWDIOはno_connect。

### 検証手順と結果
1. `kicad-cli sch erc --format json --severity-all` → **違反1件**(warning `pin_to_pin`): U1のpin38(GND、ライブラリ上の型がBidirectional)と `PWR_FLAG`(Power output)の接続。これは、host_design_notes.mdにも記録されている既知の許容範囲の警告(Picoライブラリのpin38の型が原因)で、配線ミスではない。PWR_FLAGは、+5V(J1.3)、GND(J1.4)、+3.3V(U1.36)、NEO_VDD(R23.2)の各ネットに1個ずつ置いた(電源ピンがパッシブ部品だけで給電されるネットでERCの `power_pin_not_driven` を避けるため)。
2. **配線の正しさは `kicad-cli sch export netlist`(`wire_sequence_netlist.net`)の実データで直接確認**(ERCが通っても保証にならないため)。生成スクリプトの仕様表と突き合わせ、**接続のある全43ネットのメンバー(部品参照子・ピン番号)が一致**し、仕様に無いピンが混ざったネットは無かった(ネットリストには、1ピンだけの `unconnected-*` 15本(no_connect 14ピン+NP8のDOUT)を含めて58エントリがある。ローカルラベルのネット名にはKiCadが `/` を付ける)。主なネット: `GND`(42ピン=U1のGND系9ピン+J1.4+LED1〜5のカソード+SW1/SW2+TB1〜8のpin2+NP1〜8のVSS+C1〜9の負極)、`+5V`(J1.3、U1.39、R23.1、D10.2)、`+3.3V`(U1.36と、R9〜R16のpin1)、`NEO_VDD`(NP1〜8のVDD、C1〜9の正極、R23.2、D10.1)、`W1_T`〜`W8_T`(TBn.1とRn.1)、`W1_IN`〜`W8_IN`(Rn.2、R(8+n).2、U1の対応するGPIO)、`NEO_RAW`(U1.14とR17.1)、`NEO_DIN`(R17.2とNP1.DIN)、チェーンの7本(NPnのDOUTとNP(n+1)のDIN。KiCadが付けたネット名は、ラベルのある `/NEO_4_5` だけで、他の6本は自動名 `Net-(NPn-DOUT)`(n=1,2,3,5,6,7)。生成スクリプトの仕様表では `NEO_n_n+1` と呼んでいる。接続は7本とも正しい)、`STAGEn`/`STAGEn_A`、`STATUS`/`STATUS_A`、`BTN_UP`/`BTN_DOWN`。NP8のDOUTと未使用ピンはno_connect。
3. 生成スクリプトが、異なるネットの線分の接触、ピンが他ネットの線上にあること、異なるネットのピンの一致を自動でチェックし、いずれも0件だった。
