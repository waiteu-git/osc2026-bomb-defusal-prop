## 0. 前提(ハブ経由で受け取った確定/未確定事項)

- 通信はI2C共有バスを廃止し、**区画ごとのUART専用線**。JST XH 4極: Pin1=モジュールGPIO0(UART0 TX) / Pin2=GPIO1(UART0 RX) / Pin3=VCC(5V、区画ごとのポリスイッチ。ホールドは**0.3A級(Bourns MF-RX030/72-0、秋月113076)を推奨**。0.2A品だと熱ディレーティングで余裕が無い。詳細はhost_design_notes.md) / Pin4=GND。GPIO0/1は通信専用で予約し、周辺はGPIO2〜28から選ぶ。I2Cアドレスの概念は使わない。
- **パネルは80mm×80mm(8cm角)のみで設計する**(ユーザー指示、ハブ経由 2026-09-24。100mm角案は不要になったので本書から外した)。四隅は**直径2.6mmのねじ穴**で固定し、隣り合う穴どうしの間隔が6.2cmになるように配置する(80mm角では**穴の中心はパネル縁から9mm**)。旧「穴径1cm(直径10mm)・中心位置未確認」は誤り・撤回(会議後のユーザー確定、2026-09-29)。四隅のキープアウトは**12mm角**に縮小(2026-09-29確定、旧15mm角から)。
- パネルごとの電流予算は200mA。**USBメーターで測る平均電流**として扱う(ポリスイッチは熱で動作するため)。LED輝度はファームで制限する前提でよく、数msの瞬時ピークは各モジュールのバルクコンデンサ(100µF以上)で吸収する前提(本モジュールはTM1637のVDDに100µFを入れてある)。この定義はハブが暫定採用し、**ユーザーの最終確認待ち**(ハブ回答 2026-09-27)。
- 状態表示LED(緑、GPIO直結+47Ω、解除済みの間だけ点灯)は右上角付近、四隅の穴を避けて内側。
- 共有パラメータ(シリアル番号の奇偶など)はこのモジュールでは使わない。
- **RP2350エラッタE9**(ハブ連絡事項、データシートp.1367〜1369をハブが確認): LED駆動ピンは起動直後に出力Lowにし、入力モードで使わない。点灯中(High)のピンを入力に切り替えない。影響はRP2350の**A2ステッピングのみ**で、A3以降は修正済み。ボタン(プルアップ入力)は影響なし。
- **RP2350のGPIOの5V耐性**(ハブがデータシート機能一覧p.14の原文で確認): 「GPIOs are 5 V-tolerant (powered) and 3.3 V-failsafe (unpowered)」。ただし後述のTM1637の入力しきい値(VIH=0.7×VDD)の問題とは別の話で、書き分ける(§3-2)。
- 実機検証済みの事実: (1) Pico 2のGPIOからWS2812BのDINを直結して動作、(2) 0.96"OLED(SSD1315)がPico 2 W上で動作、(3) タクトスイッチは4足のうち同じ辺の2本が常時導通し、向かい合う辺から1本ずつ使う。

## 1. 外観・ルール(公式マニュアル/KTANE Wiki/攻略ブログより)

出典: [KTANE Wiki: Morse Code](https://ktane.fandom.com/wiki/Morse_Code)(WebFetchが402で使えなかったため、内蔵ブラウザで本文と実機画像を閲覧して確認)、[攻略ブログ Part3](https://xanmark2.wordpress.com/2016/05/10/keep-talking-and-nobody-explodes%E6%94%BB%E7%95%A5%EF%BC%883%EF%BC%89/)、公式マニュアル日本語版([bombmanual.com](https://www.bombmanual.com/ja/web/index.html))。Wiki・日本語版・英語版の単語表は3者で一致。

### 外観(Wiki掲載の実機画像で確認)
金属調のパネル上に次の要素がある。
1. **左上のランプ**: 琥珀色に光るガラス管(両端に真鍮色のキャップ、配線つき)。モールス信号のパターンで点滅を繰り返す。
2. **暗い枠の中に表示部**: 上段に目盛りバー(赤い針で現在の周波数位置を示す)、その下に**オレンジ色の`3.505 MHz`表示**。表示の**左右の端に黒い三角矢印ボタン**(◀ ▶)がある。
3. **TXボタン**: 表示部の下、クリーム色の横長の四角いボタン。
4. **右上**: 水色のリングつきの丸い状態灯(共通仕様の「解除済み緑LED」の位置に当たる)。

### ルール
1. ランプの点滅をモールス符号表で読み取り、下表16語のいずれかを特定する。
2. 信号はループし、繰り返しの前に長い間隔が空く。
3. 短い点灯=点、長い点灯=線。文字間は長い間隔、単語の繰り返し前はさらに長い間隔。
4. 単語が分かったら対応する周波数に合わせ、TXボタンを1回押す。
5. **誤った周波数でTXを押すとストライク**。**正しい周波数でTXを押すと解除**。

### 検討結果
- **縦は余裕で収まる**(部品は上余白8mm〜下余白10mmの間に納まる)。**真の制約は横方向**: 表示器50.3mm+矢印キャップ9mm×2+隙間2.35mm×2+縁の余裕3.5mm×2でちょうど80.00mm。矢印ボタンが左右の端にあるので、表示器の行はy=15〜65の帯(四隅の禁止領域と重ならない範囲)に置く必要があり、実際にy=28〜47で満たしている。
- 四隅の穴は直径2.6mm・中心は縁から9mmに確定した(2026-09-29、会議後のユーザー確定)。旧「直径10mm・中心未確認(縁から5〜10mmのどこでも)」は撤回。新しい値で検算すると、部品との最小すき間は**6.7mm(ランプ左端)**で、旧値(2.0mm)より余裕が増えており、既存の配置はそのまま成立する。
- **訂正**: 初版の§2は「縦専有61mmが中央帯50mmを超える(約11mm超過)」と書いたが誤り。四隅の禁止領域は隅の正方形(現在は12mm角、2026-09-29確定。当時は15mm角)だけで、中央の列(x=12〜68、当時はx=15〜65)は縦に80mm全部使える。超過は存在しない。TXボタンを6mm角にする理由は面積の不足ではなく、部品共通化とコスト(§3-3)。
- 実機に似せる点: ランプは左上寄り(左端をx=17、隅の禁止領域(x<15)の右端から2mmの位置)、状態灯は右上、TXは下部中央、矢印は表示の左右端。
- 裏面(パネルの後ろ)の配置は未検討。Pico 2(51×21mm)・表示器・タクトスイッチの基板固定は、ケース担当のねじ穴位置とJSTコネクタの取り出し位置が確定してから決める。

#### 極性の訂正(メモリーモジュール担当の指摘で判明)
初版はカソードコモン品のOSL40562-LRを挙げていたが**誤り**。TM1637はGRID(桁)がPチャネルの電流出力、SEG(セグメント)がNチャネルの電流吸い込みという固定構造で、**共通アノード表示器専用**(データシート「The display mode supports output by common anode LED」)。カソードコモン品を繋いでも点灯しない。同じシリーズで外形・ピン配置が同一、アノードコモンの**OSL40562-IR**(¥200、在庫419個)に差し替えた。BOM金額・配置には影響しない。

#### TM1637の電気的特性(データシートV2.4で確認。初版の「RSET抵抗」の記述は誤りだったので撤回)
- **電流設定用の外付け抵抗ピンは無い**。輝度は8段階のパルス幅(1/16, 2/16, 4/16, 10/16, 11/16, 12/16, 13/16, 14/16)で調整する。
- SEG吸込電流 IOL1=20/30/50mA(最小/標準/最大)、GRID供給電流 Ioh1=80/120/180mA(VDD−2V時)、動作電圧VDD=4.5〜5.5V。
- ダイナミック点灯(1桁ずつ順に点灯)で、電流が最大になるのは1桁の全セグメントが点く瞬間。`3.505`では1桁あたり最大6セグメント(0の桁)なので、最大輝度なら理論上は瞬間的に100mA台になり得る。**輝度は低めに固定する**(ブリングアップの初期値は2=4/16)。TM1637のVDD-GND間に0.1µF+100µFを入れている(データシートの推奨どおりICの近くに)。実測は未実施で、`morse_code_bringup_procedure.md` §4の手順で行う。
- **参考回路との違い**: データシートの参考回路(Hardware connection drawing)はCLK/DIOに10kΩのプルアップ(VCCへ)と100pF(GNDへ)を入れているが、本回路は入れていない(memoryモジュールと同じ)。省略の理由は、初版では「5Vのプルアップは3.3VのPico GPIOに5Vを掛けるから」としていたが、**この理由は成り立たない**(Pico側の5V耐性は上の§0のとおり。ハブがデータシートで確認)。実際に効くのはTM1637側の話で、CLK/DIOをPicoがプッシュプルで駆動する限り、プルアップの電圧を5Vにしても**Pico出力のHighは3.3Vのまま**なので、TM1637のHigh入力しきい値(VIH=0.7×VDD=3.5V)の問題は解消しない(オープンドレイン駆動+5Vプルアップにすれば変わる可能性があるが、未検討)。DIOはPico側がプッシュプルで駆動し、ACKを読むときだけ入力に切り替えて内部プルアップに任せる(ブリングアップのスクリプト)。
- **電圧レベルの注意**(TM1637側の問題。Pico側の5V耐性とは別): 5V駆動時のHigh入力しきい値は0.7×VDD=3.5Vで、Pico 2のGPIO出力(3.3V)は規格外。memory(VDD=5V)とtimer(VDD=3.3V)で別の対処が採られており、本モジュールはmemoryと同じ5V駆動+3.3V直結にした。ブリングアップでTM1637のACKが取れるかで判定する(取れなければ、DIO/CLKのレベルシフト、VDDを3.3Vに下げる、10kΩプルアップの追加のいずれか。§7参照)。

#### セグメントのピン対応(データシートの図を座標解析して確定。実機の点灯で最終確認)
OSL40562-IRのデータシート([PDF](https://akizukidenshi.com/goodsaffix/OSL40562-IR.pdf)、`datasheet/`にも保存)の「外形とピン機能」の図は、桁をまたいで水平の母線が階段状に並ぶ描き方で、目視だけではどのピンがどの文字か断定できなかった。そこで400dpiで描画し、**座標で解析**した(証跡: `datasheet/OSL40562-IR_segment_pin_decode.png`)。

1. 図の上段のダイオード32個(4桁×A〜DP)を左から順に列として取り出し、各列の文字を並び順(A,B,C,D,E,F,G,DP)で決める。
2. 水平の母線は8本。母線と縦線の交点の黒点(ジャンクション)は16個あり、**全てが「その母線と同じ文字の列」の上に載っている**(2桁目・3桁目の列。文字が食い違う交点は0個)。つまり各母線はA〜DPの同じセグメントを4桁分まとめている(1桁目と4桁目の縦線は母線の端で終わる)。
3. 外部ピンへ降りる縦線は**2桁目の8本の列にだけ**あり(他の桁の縦線は母線で終わる)、その真下に左からピン番号 11, 7, 4, 2, 1, 10, 5, 3 が並ぶ。

結論: **A=pin11、B=pin7、C=pin4、D=pin2、E=pin1、F=pin10、G=pin5、DP=pin3**。桁選択(COM)は図の上段の数字から、DIG.1=pin12(最も左の桁)、DIG.2=pin9、DIG.3=pin8、DIG.4=pin6。回路図はこの対応で結線している。初版では目視で断定できず「暫定」としていたが、上の解析で確定した。
ただし図面から読み取った内容なので、**実機での点灯確認(ブリングアップのステップ3)が最終確認**になる。万一ずれていても、ファームウェアの変換表`REMAP`(桁ごと)で吸収でき、配線の変更は要らない。

## 4. 挙動仕様

### 4-1. モールス点滅タイミング
標準の国際モールス符号の比(1:3:7)で、視認性を優先してやや遅めにする。

| 要素 | 長さ |
|---|---|
| 単位時間T | 200ms |
| 点 | 1T = 200ms |
| 線 | 3T = 600ms |
| 符号内の点/線の間 | 1T = 200ms |
| 文字間 | 3T = 600ms |
| 単語の繰り返し前の長休止 | 7T = 1400ms |

1周の長さは語ごとに8.4〜12.8秒(表は`morse_code_bringup_procedure.md` §3)。実機のマニュアルにはタイミングの数値がないため、この値は本プロジェクトでの設計値で、`T_MS`一つで調整できる。

### 4-2. ランダム選択
起動時に16語から一様乱数で1語を選び、解除されるまで同じ語をループ送信する。開始時の表示周波数は正解と異なるものにする。

### 4-3. 周波数調整
**16種類の周波数のみを昇順/降順に巡回する方式**(連続値ではない)。◀で1つ前、▶で1つ次。端では反対側へ回り込む(ファームの定数で端止めにも変えられる)。表示は常に16種類のいずれかを4桁+小数点で示す。
理由: 実機のように0.001MHz刻みの連続値を再現すると最大100回の操作が要り展示に向かない(長押しリピートの実装も要る)。16種類の巡回なら、両方向に回り込めるので最大8回(端止めにした場合は最大15回)で、判定も「表示中のインデックス==正解のインデックス」で済む。見た目の表示は連続値方式と同じにできる。

### 4-4. TX時の判定と演出
- **正解**: 状態LED(緑)点灯、ランプ消灯、UARTでホストへ解除を通知。
- **誤り(ストライク)**: ランプを0.1秒間隔で3回速く点滅させて誤りをその場でも知らせ、UARTでホストへストライクを通知する(ストライクの回数はタイマー側で一元管理。モールス側は数えない)。その後は**同じ単語のまま**、繰り返し前の長休止から送信を再開する(語頭が分かるように)。
- 通知のデータ形式はソフト担当の設計範囲。

### 4-5. ファームウェア担当への申し送り
- `morse_code_bringup_test.py`が上の仕様を動く形で実装した試作(MicroPython)になっている。Shizuku(C++/Pico SDK)への移植時は、モールスのイベント列(`morse_events`)、周波数の巡回(`next_index`)、TM1637の送信手順(`tm_write_*`)、7セグの符号化(`freq_patterns`)をそのまま参照できる。
- TM1637の送信は、データコマンド0x40(自動加算)または0x44(固定)→アドレス0xC0|n+データ→表示制御0x88|輝度、の順。ACKを読める(DIOを入力に切り替える)ので、通信断の検出に使える。
- **7セグのセグメント対応(`REMAP`)は実測待ち**(§3-2)。本番でも桁ごとの変換表を持たせておくと、対応が違っても回路を変えずに済む。
- **E9の規則(§0)**: ランプ(GPIO2)と状態LED(GPIO8)は起動直後に出力Lowにし、入力モードで使わない(試作スクリプトは`Pin(..., Pin.OUT, value=0)`で初期化し、入力に切り替えないことをPC上のテストでも検査している)。TM1637のDIO(GPIO4)はACK読み取りの間だけ入力(内部プルアップ)に切り替えるが、LED駆動ピンではないので対象外。
- ボタンは内部プルアップ+20msのデバウンスで実装した。PC上の模擬では、チャタリングの入った押下/解放と、8msの短いグリッチ(無視される)までを検証した。実機の接点のバウンスと内部プルアップの動作は未確認。
- ストライクの点滅(約0.6秒)の間、試作スクリプトはボタン入力を取りこぼす(ブロッキング処理のため)。**本番は非ブロッキングで実装し、演出中も入力を受け付ける**こと。

### 6-3. 作成中に踏んだ落とし穴(他モジュール担当・今後のセッション向け)
1. **2.54mmピッチのピン列で、ピンから垂直に2.54mmのスタブを引くと、ちょうど隣のピンの位置に当たり短絡する。** 実際にGPIO5から下向きに出したスタブがGND(pin8)に、JSTのPin3(+5V)から下向きに出したスタブがPin4(GND)に重なり、+5VとGNDが直結した。ERCの`multiple_net_names`警告で発見できた(`power_pin_not_driven`ではない)。**ピン列上では必ず水平(列と直交する向き)にスタブを出す。**
2. **電源シンボルはピンと同じ座標に重ねても接続にならない。** ピンから少し離して置き、ワイヤーで結ぶ(host/keypadと同じ)。
3. **電源ネット(GND、+5V)にはPWR_FLAGが要る。** power:GND / power:+5Vはpower_in型なので、ネットに電源出力(power_out)が無いと全てのGND/+5Vピンが`power_pin_not_driven`になる。PWR_FLAGを各ネットに1個、電源シンボルの位置にjunctionを置いてさらに先へワイヤーで結ぶ(hostと同じ構造)。
4. **KiCad 10のシンボル配置には、各ピンの`(pin "N" (uuid ...))`と`(instances (project ...) (path ...) (reference ...))`が要る。** 無いとERCの判定が乱れた。
5. 自作シンボルのピンを数え忘れた(OSL40562-IRのBピン)。ピン数のカウント(12本)で発見。`kicad-cli`のERC JSONの座標は単位が"mm"と書かれているのに実値はmmの1/100だった(99.06mmが0.9906と出る。事実上の単位は100mm)。座標を突き合わせるときは注意。
6. ERCが通ってもネットリストで確認する、という既存の教訓は今回も有効だった(上の1〜3はERCの警告・エラーから辿れたが、意図した接続そのものはネットリストで確認)。

1. **パネルの外形・JSTコネクタの取り出し位置**(ケース担当待ち)。四隅の穴の中心位置は確定済み(直径2.6mm、縁から9mm、2026-09-29)。電気設計には影響しない。PCBレイアウトと裏面の部品配置はこれらの確定後。
2. **TM1637の電圧レベル**: 5V駆動+Pico 3.3V出力の直結はデータシートの規格外(§3-2。TM1637側のVIHの問題で、Pico側の5V耐性とは別)。実機のACK確認で判定。取れなければ、(a)DIO/CLKにレベルシフタ、(b)VDDを3.3Vに下げる(輝度が落ちる可能性)、(c)CLK/DIOに10kΩプルアップ(+100pF)を追加してデータシートの参考回路に近づける(プルアップ先はPico側が5V耐性なので5Vでも可だが、これだけではPico出力のHighは3.3Vのままなので、VIHの問題は残る可能性がある)、のいずれかに切り替える。TM1637共通試験(約¥600)はユーザーが実施し、結果はハブが集めてtimer/memory/Morseに共有する(ハブ回答)。
3. **OSL40562-IRのセグメントのピン対応は、図面から確定したが実機では未確認**(§3-2)。ブリングアップのステップ3で点灯位置を確認し、ずれていれば`REMAP`で吸収。
4. **消費電流の実測が未実施**(手順は`morse_code_bringup_procedure.md` §4)。パネル全体で200mA以内(USBメーターの平均)に収まることを、全点灯・通常表示・ランプ点滅の各状態で確認して、ここに記入する: 全点灯=___mA / 「3.505」表示=___mA / ランプ点灯中=___mA。
5. 解除後のランプの扱い(消灯のままか、点灯を保つか)と、UARTの通知データ形式はソフト担当の判断(窓口はハブ。ハブ連絡事項に一覧あり)。
6. 表示器の色(赤)が実機(オレンジ)と違う点は、フィルムを重ねる案を試すかどうか(任意)。
7. ランプ管の拡散(単一LEDで管全体が均一に光るか)は、3Dプリント品の試作で確認。暗い/ムラが出るなら、LEDを2個にするか、管の内側を拡散処理する。
