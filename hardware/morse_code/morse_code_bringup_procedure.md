# モールス信号モジュール ブリングアップ手順(配線表・期待される出力)

作成日: 2026-09-24
対象: [morse_code_bringup_test.py](morse_code_bringup_test.py)(MicroPython、Raspberry Pi Pico 2)
回路図: [morse_code.kicad_sch](morse_code.kicad_sch)(ERC: warning 1件のみ=hostと同じ既知のもの / netlist全ネット目視+機械照合PASS)
関連: [morse_code_design_notes.md](morse_code_design_notes.md)、共通の環境準備は`動作確認手順.md`冒頭を参照。

**このテストは実機未実施**。スクリプトのロジック(点滅タイミング・周波数選択・TX判定・TM1637のビット送信)はPC上で仮想クロック+偽Pinにより模擬検証済み(全チェックPASS、§6)。実機での確認は下記の手順で行う。

## 0. 必要なもの

- Raspberry Pi Pico 2(MicroPython書き込み済み)+ USBケーブル、Thonny
- ブレッドボード、ジャンパー線
- TM1637(DIP20)×1、4桁7セグ OSL40562-IR(アノードコモン)×1
- オレンジLED(OSO5CA5111A)×1、緑LED(3mm)×1、330Ω×1(ランプ用)、47Ω×1(状態LED用)
- タクトスイッチ×3(◀▶用と、TX用。ブレッドボード検証では手持ちの同種でよい)
- 0.1µFセラミック×1、100µF電解×1(TM1637のVDD-GND間、ICの近くに)
- USB電流計(平均電流の測定、§4)とテスター(状態LED・ランプの電圧測定、§2 ステップ1b)

## 2. 実行

1. Thonnyで`morse_code_bringup_test.py`を開き実行(F5)。
2. 以下の順に進む。

### ステップ1: LED確認(自動)
状態LED(緑)が0.15秒間隔で3回、続いてランプ(オレンジ)が3回点滅する。

### ステップ1b: 状態LEDとランプの電圧測定(手動、ハブ連絡事項の指示)
状態LED(3mm緑、Vf min2.9/typ3.1/max3.6V)を3.3VのGPIOから47Ωで駆動するのは余裕が小さく、電流が約4〜8mAに留まって暗い個体がある可能性がある。**一度測って記録する。**

1. Thonnyで実行中のスクリプトを止める(停止ボタン)。REPL(シェル)で次を入力する。

```
from machine import Pin
led = Pin(8, Pin.OUT, value=0)
led.value(1)      # 状態LEDを点灯したままにする
```

2. テスターで**47Ωの両端の電圧Vr**を測る。電流 I = Vr ÷ 47Ω。GPIO8とGND間の電圧Vpinも測っておくと、LEDのVf ≒ Vpin − Vr が分かる。
3. 記録する: Vr=___V、I=___mA、Vpin=___V、明るさ(暗い/普通/明るい)。終わったら`led.value(0)`。
4. 目安(ハブ連絡事項): 電流は約4〜8mA(Vr=約0.2〜0.4V)に留まる見込み。点灯しない・非常に暗い場合は、ユーザー判断(5Vレール→抵抗→LED→GPIO(Lowで点灯)の下側スイッチ駆動、またはVfの低いLEDへの変更)。
5. 参考として、ランプ(330Ω)も同様に測る(`Pin(2, Pin.OUT, value=0)`を`value(1)`)。見積りはVr≒1.2V(約3.6mA)。
6. 測定値は`morse_code_design_notes.md`§7の項目8に記入する。

スクリプトは、E9対策(ハブ連絡事項: LED駆動ピンは起動直後に出力Lowにし、入力モードで使わない)として、ランプと状態LEDのピンを`value=0`で初期化し、実行中も入力に切り替えない。

### ステップ2: TM1637のACK確認(自動)
REPLに次のどちらかが出る。

```
[ステップ2] TM1637との通信(ACK)確認
  TM1637 ACK: OK
```

`NG`の場合は§5の診断表へ。

### ステップ3: セグメント走査(目視で記録)
桁ごと・SEGごとに1箇所ずつ0.6秒間点灯し、REPLに次のように表示される(32行)。

```
  GRID1(左から1桁目) SEG1  期待=A(上)
  GRID1(左から1桁目) SEG2  期待=B(右上)
  ...
  GRID4(左から4桁目) SEG8  期待=DP(小数点)
```

表示される「期待」と**実際に光った位置**を下表に記録する(同じ表を桁ごとに)。全部一致すればデータシート図の読みは正しい。

| SEG | 期待 | 桁1で光った位置 | 桁2 | 桁3 | 桁4 |
|---|---|---|---|---|---|
| SEG1 | A(上) | | | | |
| SEG2 | B(右上) | | | | |
| SEG3 | C(右下) | | | | |
| SEG4 | D(下) | | | | |
| SEG5 | E(左下) | | | | |
| SEG6 | F(左上) | | | | |
| SEG7 | G(中) | | | | |
| SEG8 | DP(小数点) | | | | |

ずれていた場合: スクリプト冒頭の`REMAP[桁][論理セグメント] = 実際に光ったSEG番号-1`を書き換える(論理セグメントの順はA,B,C,D,E,F,G,DP)。例えば桁1で「論理Aを光らせたいのに実際はSEG2側が光る」なら`REMAP[0][0] = 1`。**回路・部品の変更は不要**で、本番ファームでも同じ変換表を持たせればよい。桁ごとにずれ方が違っても`REMAP`は桁ごとに持てる。

### ステップ4: 全点灯 → 「3.505」(目視)
全セグメントが1秒点灯した後、`3.505`(左端の桁の後ろに小数点)が3秒間表示される。数字が正しく読めなければ、ステップ3の記録どおりに`REMAP`を直して再実行。

### ステップ5: 対話デモ(自動でループ)
REPLに次のように出て、ランプが送信語をモールスで点滅し続ける。

```
[新ラウンド] 送信語=halls  正解周波数=3.515 MHz  (テスト用に表示。本番では表示しない)
  1周の長さ = 10800 ms
```

- ◀▶を押すと表示が16種類の周波数を1つずつ巡回する(`  ▶ 周波数 3.515 MHz`)。端では反対側へ回り込む。
- TXを押す:
  - 誤り → `  TX: ストライク(周波数 3.505 は誤り。ホストへ通知する想定)`。ランプが0.1秒間隔で3回速く点滅し、その後は長休止から送信を再開。
  - 正解 → `  TX: 正解! 解除(状態LED点灯、ランプ消灯)`。状態LED(緑)が3秒点灯した後、次のラウンドへ。
- 終了はCtrl+C。

モールス点滅の確認方法: 単位T=200ms。点=0.2秒、線=0.6秒、文字間=0.6秒、繰り返し前の休止=1.4秒。REPLに出る「送信語」と見比べて読めること。

## 3. 1周の長さ(T=200ms、繰り返し前の休止1.4秒を含む)

| 語 | 周波数(MHz) | 1周(ms) | 語 | 周波数(MHz) | 1周(ms) |
|---|---:|---:|---|---:|---:|
| shell | 3.505 | 10000 | flick | 3.555 | 12000 |
| halls | 3.515 | 10800 | bombs | 3.565 | 12000 |
| slick | 3.522 | 11200 | break | 3.572 | 10000 |
| trick | 3.532 | 10400 | brick | 3.575 | 11600 |
| boxes | 3.535 | 11200 | steak | 3.582 | 8400 |
| leaks | 3.542 | 9600 | sting | 3.592 | 8800 |
| strobe | 3.545 | 11600 | vector | 3.595 | 12800 |
| bistro | 3.552 | 12000 | beats | 3.600 | 8400 |

8.4秒〜12.8秒/周。実機のゲームでは同じ語が何周も繰り返されるので、この長さなら読み取りの練習と展示のテンポに支障はない見込み(体感で長すぎる/短すぎる場合は`T_MS`だけ変えればよい)。

## 4. 電流の確認(パネルごとの電流予算200mA。USBメーターで測る平均電流)

TM1637の仕様(データシートV2.4): SEG吸込電流 IOL1 = 20/30/50 mA(最小/標準/最大)、GRID供給電流 Ioh1 = 80/120/180 mA(VDD-2V時)。輝度は8段階のパルス幅(1/16〜14/16)で調整でき、**電流設定用の外付け抵抗は無い**。1桁の全セグメント(最大8個)が同時に点灯する瞬間電流が最大なので、次を測る。

1. USB電流計(またはテスターの電流レンジ)をPicoの5V供給(VBUS→Pico、またはTM1637 VDD)に直列に入れる。
2. ステップ4の最初の全点灯(`8.8.8.8.`)、「3.505」表示中、ステップ5のランプ点滅中の各状態で電流を読む。
3. 判定の目安: **USBメーターの表示(平均電流)が、全点灯時でも200mAを大きく下回ること**(ハブ連絡事項: パネルごとの200mAは平均電流の予算。ポリスイッチは熱で動作し、0.3A級(MF-RX030/72-0)を推奨。定義の最終確認はユーザー待ち。数msの瞬時ピークはTM1637のVDDの100µFで吸収する前提)。超える/近い場合は`BRIGHTNESS`を下げる(初期値2=4/16)。本番ファームも同じ上限を守ること。
4. 測定値は`morse_code_design_notes.md`§7に記入する(現時点では未測定)。

## 5. うまくいかないとき

| 症状 | 原因の候補と対処 |
|---|---|
| ACK NG | ①TM1637の電源: VDDに4.5〜5.5Vが来ているか(USB給電ならVBUS pin40)、GND共通か。②CLK/DIOの配線違い(GPIO3=CLK、GPIO4=DIO)。③**電圧レベル**: TM1637は5V駆動でHigh入力しきい値=0.7×VDD=3.5V。Picoの3.3V出力は規格外で、個体によっては認識されない。対策案: (a)DIO/CLKにレベルシフタ(74HCT系やBSS138等)、(b)VDDを3.3Vに下げる(輝度は落ちるが動作する場合が多い。timerモジュールはこの方式)、(c)CLK/DIOに10kΩプルアップ(+100pF)を追加(データシートの参考回路は10kΩ+100pFを持つ)。Pico側のGPIOは5V耐性があるのでプルアップ先は5Vでも可だが、Pico出力のHighは3.3Vのままなので、これだけではTM1637のVIH(3.5V)の問題は残る可能性がある(TM1637側の問題とPico側の5V耐性は別)。memoryモジュールも同じ懸念を持つので、結果をハブに共有すること |
| 何も光らない(ACKはOK) | 表示器の極性違い(コモンカソード品OSL40562-LRを買っていないか。**アノードコモンのOSL40562-IR**が必要)。桁選択(pin12/9/8/6)とGRID1〜4の接続を確認 |
| 一部の桁/セグメントだけ点かない | ステップ3の記録表で該当のSEG/GRIDの半田・ジャンパーを確認 |
| 数字が乱れる | ステップ3の対応がずれている→`REMAP`を修正(§2ステップ3) |
| ボタンが反応しない | タクトスイッチの足の選び方(同じ辺の2本は常時導通)。ボタンの一方がGPIO、他方がGNDか |
| ランプが暗い/点かない | LEDの向き(アノード側が330Ω→GPIO側)。電流は約3.6mA(GPIO既定の4mA以内)で、このLEDは公称35000mcd(20mAで約38000mcd)の高輝度品なので通常は十分明るい。暗い場合は抵抗を220Ω程度まで下げて試す(47Ωは理論25mAでGPIOの許容を超えるので不可)。それでも不足なら本番ではNPNトランジスタ駆動を検討 |

## 6. PC上での模擬検証(実施済み、全PASS)

仮想クロック(MicroPythonと同じ2^30で折り返すティック)と偽の`machine.Pin`でスクリプトを読み込んで検証する。コードは`tools/test_bringup_offdevice.py`(`python tools/test_bringup_offdevice.py`で再実行できる)。**`--mutants`を付けると、スクリプトを20通りに壊して(デバウンス除去、ティック折り返し非対応、線を1Tで送る、ACK開放の遅れ、ビット順の反転、LED駆動ピンの起動時Low指定の削除・入力への切り替えなど)テストが検出できることを確認する。現在は20件全て検出。**

- 語/周波数表が公式表(KTANE Wiki)と一致。モールス符号が独立に書き下したITU符号表および設計メモ§1の表(16語)と一致。イベント列をテスト側で独立に組み立てた期待値と比較(16語すべて)。1周の長さが§3の表(16語)と一致
- `3.505`の7セグ符号化(先頭桁だけDP)、`REMAP`の桁ごとの適用、周波数の巡回/端止め
- E9: ランプ・状態LEDのピンを起動時に出力Lowで初期化し、ステップ1/3/4とラウンド(ストライク/正解を含む)の間、これらを入力に切り替えないこと
- TM1637のビット送信(LSBファースト、START/STOP)をCLK/DIOの変化と時刻から復号し、`tm_write_grid`=`[0x44]→[0xC0|g, data]→[0x88|輝度]`、`tm_show`=`[0x40]→[0xC0, 4桁+2桁分]→[0x88|輝度]`、CLKの幅が4us以上、ACKの9クロック目でDIOが入力(開放)になっていること、ACK成功/失敗の両方を確認
- 1ラウンドの模擬: TXの8msグリッチは無視され、チャタリングを含む押下でストライクは1回だけ。ストライク→▶→**1周以上経ってから**正解。ストライク前のランプの変化、ストライクの3回点滅(100ms周期)、ストライク後の長休止からの再開と**1周の折り返し・ティックの折り返しをまたぐ全ての変化**が、理想の時刻表(200ms格子)から±3ms以内。正解後にランプが点灯しない、状態LEDの点灯/消灯。仮想時間の上限つき(ラウンドが終わらなければ失敗になる)

実機でのみ確認できること(未確認): 表示器のセグメントが図面どおりの位置で光ること(ピン対応自体はデータシート図から確定済み)、TM1637の3.3Vロジックでの動作、実際の消費電流、接点のバウンス、目視でのモールスの読みやすさ。
