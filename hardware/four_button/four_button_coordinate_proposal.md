# 4ボタン統合基板(キーパッド+サイモン) 配置座標案(第一段階)

作成日: 2026-09-30(2026-10-01更新: ユーザー回答「モードごとにスイッチ配置を丸ごと替える(キャップ・面板も差し替え、グリッドとひし形は同時に存在しない)」を反映し、サイモンのひし形キャップの縮小を撤回)
担当: サイモンモジュール ハードウェア設計セッション(統合基板のKiCad主担当、ハブ暫定)。
キーパッド担当セッションと直接すり合わせ、状態LED位置の衝突を解消済み。**本ファイルはハブの依頼「(1)座標案とLED位置 (2)ソケット・スイッチ個数 (3)担当分けとプロジェクト名の確認」に対する回答。基板の配置・配線(KiCad)は、ユーザー確認後に着手する。**

## 0. 前提

- パネル80×80mm。取付穴Ø2.6mm(非めっき)、中心はパネル縁から9mm=中心座標(±31,±31)(中心を原点、+x右・+y下)。
- 四隅キープアウト12×12mm(絶対座標の角、例: 右上は x∈[68,80]かつy∈[0,12])。
- MXホットスワップソケットのフットプリント: `hardware/button/keyswitches.pretty/Kailh_socket_MX.kicad_mod`(daprice版、ボタン担当が保存済みのファイルを自分でも検証)。
  - 外形(F.Fab)は±7.5mm四方(15×15mm)。パッド2個(2.55×2.5mm、裏面B.Cuのみ)。非めっき穴5個(中心Ø3.99、側面Ø1.70×2、スイッチ足Ø3.00×2)。
  - **穴間隔を自分で再計算し、ハブ・ボタン担当の報告(0.489mm)と一致することを確認した**(側面穴と足穴の間、共通ルールの下限0.45mmを0.039mm上回るだけの最小値)。
- MXスイッチの実寸(未購入・一般値、ハブが提示): 本体(トップハウジング)15.6×15.6mm(半幅7.8mm)、1uキーキャップ約18×18mm(半幅9mm)、プレート穴14×14mm相当。
- **プレート(スイッチ保持・荷重受け)が必須**(ボタン担当の下調べ: ソケットの爪だけではスイッチが抜けてしまう)。

## 1. 配置の考え方(キーパッド担当と一致した着想)

サイモンのひし形は**上下左右の軸方向**に伸びる(点は(0,±Rd)と(±Rd,0))。キーパッドの2×2グリッドを**対角4方向**(±d,±d)に置くと、軸とは方向が異なるため干渉しにくい。さらに、**グリッドの対角オフセットdが「グリッドのキャップ半幅+サイモンのキャップ半幅」以上であれば、サイモンの半径Rdの値によらず自動的に非干渉になる**(下記2-3で証明)。この性質により、キーパッド側の座標とサイモン側の座標を独立に決められた。

## 2. 座標(中心を原点(0,0)、+x=右、+y=下、mm)

### 2-1. キーパッド(2×2グリッド、キーパッド担当の提案どおり)

| キー | 座標 | 備考 |
|---|---:|---|
| A(左上) | (−19, −19) | |
| B(右上) | (19, −19) | |
| C(左下) | (−19, 19) | |
| D(右下) | (19, 19) | |

d=19mm。1uキャップ(半幅9mm)の角(28,28)から取付穴中心(31,31)までの対角距離は4.24mm(キーパッド担当が算出、自分も再確認)。ピッチ38mm、キー同士(18mmキャップ)は無干渉。

### 2-2. サイモン(ひし形、本セッションの提案)

| キー | 座標 | 色 |
|---|---:|---|
| Blue(上) | (0, −17) | 青 |
| Yellow(右) | (17, 0) | 黄 |
| Green(下) | (0, 17) | 緑 |
| Red(左) | (−17, 0) | 赤 |

Rd=17mm。根拠: MX本体(半幅7.8mm)同士が隣接軸間(例: 上と右、Δx=Δy=17mm)で衝突しない最小値は15.6mm(=本体1辺)。17mmは1.4mmの余裕を持たせた値(**ユーザーの「もっと密集させたい」という以前の要望を踏まえ、無理のない範囲で最小に近い値**)。この値はキャップの大きさに関わらず有効(下記2-3参照)。

キーキャップは**ひし形の自作カスタムキャップ**(実物の見た目を継承、ハブの「再現の方針」でサイモンのひし形配置は簡略化しない対象と明記)。**寸法は単独サイモン基板案と同じ29mm(先端から先端)=半対角14.5mmのまま**(2026-10-01: ユーザー回答によりキャップ縮小は撤回、下記2-3参照)。

### 2-3. グリッドとひし形の関係(2026-10-01更新: モードは同時に存在しない)

**ユーザー回答: 「サイモンのときと4ボタンのときで、それぞれスイッチの配置を変える」**。グリッドのキーキャップとひし形のキーキャップは**同時には存在しない**(モードごとに4個だけソケットへ挿し、パネル面板もモードごと差し替える運用)。そのため、**キャップ同士(グリッド1uキャップとサイモンのひし形キャップ)の干渉は考える必要がない**。§2-2の29mmという寸法は、キーパッド側のキャップとは無関係に決めてよい。

常時基板上に実装される**ソケット本体(15×15mmの外形・パッド・穴)と、モード実行時に挿さる実際のMXスイッチ本体(15.6×15.6mm)** は、グリッドとひし形の両方が同時に存在する(ソケットは常時、スイッチ本体は使用中のモードの分だけだが、干渉チェックは安全側にソケット同士で行う)。以下を確認した。

| 組み合わせ(最も近い4組) | ソケット外形(15×15)の余裕 | 本体(15.6×15.6)の余裕 |
|---|---:|---:|
| A(左上)↔Blue(上) | d−(半幅7.5+半幅7.5)=4.0mm | d−(半幅7.8+半幅7.8)=3.4mm |
| A(左上)↔Red(左) | 同上 | 同上 |
| B(右上)↔Blue(上) | 同上 | 同上 |
| B(右上)↔Yellow(右) | 同上 | 同上 |
| (他8組) | 余裕大(37mm前後) | 余裕大 |

d(19)−7.8×2=3.4mmの余裕(ハブが再計算、自分も確認)。Rdの値には依存しない(グリッド側の対角オフセットdだけで決まる)。

**サイモン自身のひし形キャップ同士(29mm、半対角14.5mm)の間隔**: 隣り合う軸(例: 上と右)のキャップ中心間のL1距離は2×Rd=34mm。ひし形(L1球)同士が重ならない条件は34mm>14.5+14.5=29mmで、**余裕5.0mm**(ハブの検算と一致)。キャップ先端(絶対座標y=8.5等)は、パネル端まで8.5mm、最寄りの取付穴(31,31)までは約31.0mm離れており、いずれも問題ない。

以上により、**Rd=17mm・サイモンのひし形キャップ29mmのまま**で確定してよい(キーパッド側のキャップ寸法とは独立)。

## 3. 状態LEDの位置(衝突解消)

キーパッド担当の指摘どおり、旧位置(21,−21)は新しいグリッド座標(d=19、キャップ半幅9)のB(右上)キャップの直下に入ってしまう(完全に隠れる)。

**新しい位置を計算して提案: 絶対座標(60, 6)、中心相対で(+20, −34)。**

| 対象 | 距離 | 判定 |
|---|---:|---|
| B(右上)キャップ縁(グリッド1u、18mm) | 6.0mm | クリア |
| Blue(上)キャップ縁(ひし形、29mmに復元、下記) | 15.9mm | クリア |
| 四隅キープアウト(x<68でy<12は対象外) | x=60<68 | 対象外 |
| 取付穴(71,9)中心 | 11.4mm(ネジ頭半径2.5mmを引くと8.9mm) | クリア |
| パネル上端(y=0) | 6mm | 他モジュールの状態LED位置(5〜8mm程度)と同程度 |

パネル上辺寄り、B(右上)キーとBlue(上)キーの間に生まれる隙間(両方より上、y<12の帯)を使う。**「右上付近」という共通仕様は満たすが、他モジュールのような角ぴったりの位置ではない**(グリッドとひし形の両方を右上角近くに置いたことの直接の帰結)。

**訂正の経緯**: 2026-09-30時点では、Blueキャップを18mm(縮小案)として計算し、当初13.6mm→キーパッド担当の指摘で正しい形状(ひし形、正方形でなく)に基づく19.8mmに訂正した。**2026-10-01、ひし形キャップが29mmに戻った(§2-3)ため、再計算して15.9mm。** 距離の計算方法(ひし形の最近接の辺までのユークリッド距離)自体は正しいものを使い続けている。いずれの数値でもクリア(状態LEDの位置(60,6)自体は変更なし)。

## 4. 必要なソケット・スイッチの個数

- **ソケット(はんだ付け、常時実装): 8個**(グリッド4+ひし形4)。両モードの基板を1枚で兼用するため、使わない側のソケットも常に基板上にある(空のまま)。
- **スイッチ(差し込み、モードにより4個だけ使用): 運用上は8個(両モード分を常備、差し替え時間を減らす)を推奨。** ユーザーが別ルートで10個(¥800)購入予定とのことで、8個+予備2個として使える。
- **キーキャップ: グリッド用4個(1u、18mm角相当)+ひし形用4個(自作、29mm対角、単独サイモン案と同寸法)。** ひし形は3Dプリント/レーザー加工の自作(単独サイモン案と同じ方針)。両モードのキャップ・面板一式を常備し、モードごと丸ごと差し替える(上記§5の4番目の項目)。

## 5. 未決事項(ユーザー・ハブ確認が必要)

1. **サイモンの発光方式**(最重要、決定済み・調査中): **(c)透明/半透明ハウジングのMXスイッチ+基板側LEDに決定**(ハブ、2026-09-30)。スイッチの型番(LEDの位置、3ピン/5ピン、納期)はハブが調査中。詳細は§5-補。
2. ~~サイモンのひし形キャップの寸法縮小~~ → **解決(2026-10-01)**: モードは同時に存在しないため、キャップ同士の干渉を考える必要はない。単独案の29mmのまま(§2-3)。
3. **モード切替の前提**(ハブから整理を依頼された点): ソフトウェアが「今どちらのモードか」をどう知るかが未定。ハードとして、**基板上に2ポジションのモード選択スイッチ(GPIO+GND、内部プルアップ)を1個追加する案を提案**(GPIO1本を追加で使用、下記§6)。これなら同じファームウェアを両モードで使い回せる。再フラッシュ方式(モードごとに別ファームを書き込む)でもハードの変更は不要。ハブ暫定でスイッチ案に賛成、最終決定はソフト担当・ユーザー判断。
4. **パネル(見た目の板)の扱い**: **ユーザー回答により確定(2026-10-01)**: 基板(ソケット8個)は共通のまま、キーキャップと同様にパネル面板・スイッチ一式をモードごとに丸ごと差し替える。使わない側の4ソケットは、その時点では面板の下に隠れる(面板に穴が無いか、パネルごと別部品のため露出しない)。
5. **ソケット外形(15×15mm)同士の余裕4.0mm・本体(15.6mm角)同士の余裕3.4mm**(§2-3)は、常時実装されるソケット同士の話なので、JLCPCBの製造誤差を考慮しても十分な余裕がある(0.2mm程度の誤差に対し余裕3.4〜4.0mmは問題ない)。

## 5-補. 発光方式(c)の下調べ(2026-09-30、ハブ決定を受けて着手。KiCad配置は未着手のまま)

ハブから、発光方式は**(c)透明/半透明ハウジングのMX互換スイッチ+基板側LED**に決定との連絡があった。キャップ寸法の最終回答が届くまでKiCad配置には着手しないが、LED footprint の調査を先行した。

- **daprice/keyswitches.pretty(GitHub本家、ボタン担当が保存したものと同じライブラリ)を確認したが、LED用の専用フットプリントは存在しない**(全21ファイルのファイル名・内容を確認、"LED"を含むファイル名なし)。READMEに「プレート外形とLED取り付け領域はEco2.Userレイヤーに記載」とあるが、実際のフットプリントファイル(`SW_MX.kicad_mod`)のEco2.User要素はプレート外形(13.8mm角)のみで、LED専用のマーキングは見当たらなかった。
- したがって、**LEDのパッド・穴は自分たちで追加する必要がある**(ソケットのフットプリントを複製し、LED用のパッド/穴を足す)。
- **LEDの位置(スイッチ中心からのオフセット)は、購入するスイッチの型番に依存する**(Cherry/Kailh/Gateron等でLED窓の位置が異なりうる)。一次資料(daprice本家含む)から確定値を得られなかったため、**現時点では未確定・仮の値**として扱う: 一般的な「サウスフェイシング(下向き)LED」設計に倣い、スイッチ中心から**下方向(南側)に約5.08mm**の位置に3mmまたは5mmLEDを置く案を仮置きする(格子2.54mmの倍数で他のフットプリント座標と整合させた値。実物のスイッチ/データシートが届き次第、実測して確定する)。
- サイモンの4色LEDは、この仮のLED位置(各スイッチの「南」)を基準に、ひし形の向き(上/右/下/左)ごとにLEDの向きも回転させる想定。
- 駆動回路(2SC1815ローサイド、4.7kΩ+150Ω/330Ω)は単独案のまま流用できる見込みで、LEDの実体(3mm/5mm THT想定)が変わっても抵抗値の再計算のみで対応可能。

## 6. GPIOへの影響(参考、回路図は未着手)

- グリッドとひし形は**同時に1組しか実装されない**(もう一方はソケットが空)ため、**ボタン入力4本(GP2〜GP5)を両モードで共用できる**(例: GP2=グリッドA/ひし形Red、GP3=グリッドB/ひし形Blue、GP4=グリッドC/ひし形Green、GP5=グリッドD/ひし形Yellow。対応は仮、ファーム側で自由に決められる)。
- ひし形の色LED駆動(GP6〜GP9、4.7kΩ+2SC1815)はグリッドモードでは未使用のまま(単独サイモン案から継続)。
- 状態LED(GP10)は共通。
- モード選択スイッチを追加する場合、GP11を提案(内部プルアップ、GNDで「ひし形モード」など)。
- 単独キーパッド案のGPIO6(状態LED)は、統合基板ではGPIO10に統一する(キーパッド担当の提案どおり)。

## 7. キーパッド担当からの指摘事項の反映

- ERC 0件化(no_connect/PWR_FLAG)、PicoのGNDピン全接続、5V入力の100µFバルクコンデンサは、統合基板の新規回路図で最初から対応する(単独キーパッド案の積み残しを引き継がない)。
- 単独キーパッド案のSW_PUSH-12mmタクトスイッチのフットプリントは使わない(MXホットスワップソケットに全面置き換え)。

## 8-補. Pico 2 H(浮かせ実装)への対応(2026-09-30、ハブ追加連絡)

タイマー・ボタン・複雑ワイヤ・4ボタン統合の4基板は、Picoをピンヘッダで約2.5mm浮かせて実装する方式に統一(`hardware/shared_lib/`の`OSC_Shared:Pico_TH40`シンボル+`OSC_Shared:RPi_Pico_TH_Headers`フットプリント)。KiCadプロジェクトを作る際、simonの回路図を複製した上でPicoをこのライブラリに差し替える。裏面のMXソケット(SMD)がPicoの下に入る配置になる場合は、浮き量2.5mmの範囲に収まる部品高さか確認する(ソケットのパッドは基板面のみで背が低いため、通常は問題ない見込みだが実物確認が必要)。Pico 2 Hのデバッグ用JST SH 3極コネクタ(上面側)とキー配置・プレートとの干渉も、実寸確認の対象に追加する。
