## 4. 既知のリスクと過去の訂正

### 既知のリスク
1. **電源(案A)**: 最悪1.4AがPicoのmicroUSB端子・内部配線を通る。データシートにVBUSピンの許容電流の規定が見当たらない。ケーブル抵抗による電圧降下(1mの28AWGで約0.6V)があり、VBUSの推奨範囲(4.5V〜)を割りうる。入口の保護は充電器側だけ。
2. **ポリスイッチ**: 60℃近くでは0.3A級でもホールドが0.19Aに下がり、200mAを割る(ケース内は50℃以下に)。トリップは秒オーダーで、短絡中は一時的にレールが落ちうる。footprintは未作成(KiCad標準にMF-RX用が無い。リード間隔5.1mmの2ピンTHTを作る必要がある)。
3. **UART**: 3Mbps級を狙う速度・PIO UART 4本の実現性は、実機で未検証(ソフト実装待ち)。ケーブル長・ノイズの影響も未検証。PCB化ではUART配線の下面にGNDベタが要件(ハブ確定)。ユニバーサル基板の手配線だと配線が長く、速度が出にくい可能性がある。
4. **UARTの線の浮き(私の指摘、設計変更ではなくソフト側の設定)**: プルアップ無しのため、起動直後〜ピン設定前や、モジュール未接続のときは線が浮く。ソフトは、ホストのTXを起動直後にHighにし、モジュール側のRXは内部プルアップを有効にするのが安全。
5. **RP2350エラッタE9**(ハブ連絡事項.md、サイモン担当がデータシートで確認、ハブ・私は未検証): LED駆動ピンは起動直後に出力Lowにし、入力モードで使わない。ホストではGP7(SHARED_LED)が該当する。
6. **白色LED(OSW54K3131A)の3.3V駆動**: Vf(max3.6V)が供給電圧3.3Vを超えるため、個体によっては暗い/点灯しない可能性がある。抵抗100〜150Ωで実測し、明るい個体を選別する方針(決着済み)。実機の点灯確認はウィジェット側の試作待ち。
7. **J7のOLED消費電流(案C = 2.42インチの場合)**: ウィジェット設計メモ(Waveshare仕様)では、全点灯約196mA/全消灯7.3mA(3.3V)。文字表示だけの実消費電流は、9/26に着荷した現物で実測する予定で、まだ値が無い。3V3(OUT)の外部負荷は、全点灯の最悪で約196mAに白色LEDの数mA〜10mAを足した約206mAで、Picoの推奨(300mA未満)には収まるが、ハブの目安「半分以下(150mA)」は超える。文字表示のみなら大きく下がる見込みだが未確認。5V側では約160mA相当(変換効率85%と仮定した概算)で、§3の最悪合計は約1.4Aから約1.5Aに増える。0.96インチ(案A)なら約20〜30mAで問題なし。
8. **ホストの消費電流の根拠が弱い**: Pico 2 Wのデータシートに消費電流の数値が見当たらず、ホストの見積もりは他人の実測例(電池電圧での測定)に頼っている。5V入力時の値は未確認。
9. **他担当の資料に古い記載が残っている**: `timer_design_notes.md` に「ホールド約200mA」が残っている(現在は0.3A級を推奨)。ハブ側で確認してほしい。

### 過去に自分が訂正した誤り
1. **白色LEDの3.3V駆動(9/17)**: 「ユーザーが以前同種のLEDを3.3Vで問題なく使えた」を根拠にしたが、その実績はキーパッドの緑色LED(Vf約2.0〜2.2V)のことで、白色LED(Vf 2.9〜3.6V)とは水準が違った。OSC2026の指摘で訂正し、「一部の個体は実用上点灯しない可能性がある」というリスクとして扱い直した(ホスト側は変更なし)。
2. **ポリスイッチのホールド電流(9/24)**: 「ホールド約200mA」をピーク予算200mAと同じ値で採用していたが、熱ディレーティングで余裕ゼロと判明(40℃で0.16A)。0.3A級(MF-RX030)へ変更した。同時に、回路図のF1〜F6のValueが暫定の「500mA」のまま設計メモの記載と矛盾していたのも修正した。
3. **ブレッドボード確認ページの記述(未訂正)**: 「プルアップ抵抗を忘れずに——これが無いと通信できない」と書いたが、実際に使ったOLEDモジュールは内蔵プルアップ付きで、外付け無しで動作した(9/24)。モジュールによっては正しいが、断定が言い過ぎ。公開ページはまだ更新していない。
4. **検証レビューの誤検出(9/15)**: ワークフローのレビュー担当が「J1のPin1/Pin3が入れ替わっている」などを重大な問題として報告したが、KiCadのライブラリ空間がY軸上向きであることを考慮していないための誤検出だった(ネットリストで確認して訂正)。レビュー用の指示にY軸の反転規則を書いていなかったのが原因の一つ。
5. **古くなった説明文(9/24訂正)**: U1のDescriptionの「I2C0 slave host controller」(ホストはマスター)やR1/R2の「共有バス用」など、設計変更に追従していない文言を更新した。

## 6. ホスト固有の項目

1. **電源入力の案A/B/C**: 上の§2のとおり。案A(USB充電器→Picoのmicro USB)が当面、案B(基板に外部5V入力を設ける)がPCB化での推奨、案C(Type-C入力)は不採用。回路図は案A相当のまま。バルクコンデンサ470µF以上(耐圧16V以上、ハブ共通ルールに合わせた)は案A/B共通で推奨だが、現回路図には未搭載。
2. **MF-RX030の採用状況**: KiCadのF1〜F6のValue=300mA、Description=推奨品番を反映済み。footprintは空欄のまま(自作が必要)。発注は未確認。
3. **各モジュールの常用電流の実測待ち**: §2のとおり(キーパッド、サイモン、タイマーが仮置き。迷路は表示器の決定待ち。他は把握していない)。
4. **UARTのハード/PIO割当とソフト担当との調整**: ハードUARTはJ1(GP8/9=UART1)とJ2(GP12/13=UART0)。J3〜J6はPIO UART(GP10/11、GP14/15、GP16/17、GP18/19)。TXが偶数、RXが奇数の隣接ペア。ソフト担当からの受領確認は届いていない。ハブ経由の調整状況は、私からは見えない。
5. **ボタン復活とbit3/5/6**: **ホストのハード変更は不要**。BATT3(bit3)はJ8 Pin5(GP5)に既にある。bit5/bit6(CAR/FRK点灯)は、ウィジェット設計メモ§6のとおり、ホストが表示するOLEDの略称とSHARED_LED(GP7)の点灯の組み合わせから、ホストのソフトが作る。影響は、ウィジェット側でBATT3のスイッチとインジケーター(LED+OLED)の優先度が「後回し可」から「必須」に戻ること(ハブ連絡事項.mdのとおり)と、ホストのファームがbit3/5/6を組み立てる必要があること。
6. **UART項目の一覧(ソフト担当への申し送り)**:

| 方向 | 項目 | 使うモジュール | 状態 |
|---|---|---|---|
| ホスト→モジュール | 共有情報バイト1バイト(bit0=シリアル末尾が奇数、bit1=母音を含む、bit2=電池2本以上、bit3=電池3本以上、bit4=パラレルポート、bit5=CAR点灯、bit6=FRK点灯、bit7=予備) | ワイヤー系、サイモン(bit1)、ボタン(bit2/3/5/6)、複雑ワイヤ(bit0/bit2/bit4)ほか | 内容は確定。送る頻度は「通信のたびに毎回」の方針(9/16、UARTでも維持するかはソフト判断) |
| ホスト→モジュール | 爆弾全体の現在のストライク数(0/1/2以上) | サイモン(必須) | **未定義(要追加)**。共有情報バイトに入らない |
| ホスト→モジュール | カウントダウンのタイマー表示値 | ボタン(4/1/5を含むとき離す) | 未定義(ホスト側で判定する案もあり、ソフト判断) |
| ホスト→モジュール | 残り時間(MM:SS)・ストライク数(失敗回数表示) | タイマー/失敗カウント表示ユニット(表示専用) | 正本(typ)に記載あり、形式は未定 |
| ホスト→モジュール(決めごと) | Memoryはステージごとに、表示数字とボタン4個のラベル(1〜4)を再抽選する(ステージ内は固定)。ストライク後にステージ1を再抽選するかを決める | Memory | 正本(typ)に記載あり。ソフト判断(9/27追記で§6の突き合わせにより追加) |
| モジュール→ホスト(決めごと) | Morse Codeの解除後のランプの扱いを、通知形式に含める | Morse Code | 正本(typ)に記載あり、形式は未定(同上) |
| モジュール→ホスト | 状態(未解除/解除済み/ストライク発生) | 全パズルモジュール | 方針は確定、形式は未定 |
| 両方向 | モジュール種別の識別(どの区画にどのモジュールが挿さっているか) | 全モジュール | I2Cアドレスの廃止に伴い、ソフト側のプロトコルで決める(ハブ連絡) |

ソフト担当へ伝えるハード側の前提: (a) 各区画の線は push-pull・プルアップなし・3.3V論理。(b) J8のスイッチ入力(GP2〜6)は内部プルアップ(PULL_UP)前提で、スイッチONがLow。(c) GP7はLED出力で、E9規則により起動直後に出力Low、入力モードにしない。(d) GP0/GP1はI2C0(OLED、アドレス0x3C、製品によっては0x3D)。(e) Wi-Fi(CYW43439)を使うかは未決で、使うと消費電流が増える。

## 7. ハブに決めてほしいこと

1. **ホスト基板の作り方**(PCB発注かユニバーサル基板か)と、その期限。PCBなら10/3頃までに発注(目安、納期は未確認)。
2. **電源入力**: 案Aで固定して進めるか、案B(回路変更あり)にするか。ユーザー承認の結果。
3. **UARTプロトコルの確定期限**(ボーレート、フレーミング、§6の項目、特にストライク数とタイマー値)と、ソフト担当への受領確認の取り方。
4. **各モジュールの常用電流の実測の集約担当と期限**(仮置き分の確定)。
5. **ケース担当への確認**: ホスト基板の固定方法・外形・JSTの取り出し辺の回答期限。
6. **ウィジェット表示器の案E**を選ぶ場合の、ホスト変更の内容。案Cの場合のJ7の3.3V電流(文字表示での実測値)の確認。ハブ決定(9/27): ウィジェット担当の設計メモの値を使って、3V3(OUT)の合計を300mA未満で見る(上記のとおり最悪約206mAで収まる)。
7. **他資料の古い記載の更新**(`timer_design_notes.md` の「ホールド約200mA」など)。
