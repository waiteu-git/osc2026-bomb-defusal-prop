# OSC2026 爆弾解除ゲーム ホスト基盤 設計メモ

最終更新: 2026-09-27 / 回路図: `hardware/host/host.kicad_sch`(kicad-cli ERC エラー0・既知の警告1、ネットリスト全ネット確認済み)
姉妹モジュール `hardware/keypad/keypad.kicad_sch` を実装例・反面教師として参照した。全体の確定事項は `ハブ連絡事項.md` と `爆弾解除モジュール案.typ` が正本。

**2026-09-27: ホスト基盤を独立基板ではなく、タイマーモジュール筐体内のPico 2枚構成(1枚目=マスター/タイマー担当、2枚目=このファイル)に再設計した。** 従来「ホスト基盤(独立筐体)」として計画していたものは廃止し、タイマーモジュールの筐体内にPico 2枚を同居させる構成に変更。1枚目(Board1、`hardware/timer/timer.kicad_sch`、今回は変更対象外)がタイマー/失敗回数の管理と爆弾全体の最終判定を担当し、外部電源(USB、将来的に乾電池の可能性あり)を受けて2枚目へ給電する。2枚目(Board2、このファイル)は従来ホストが担っていた「各パズルモジュールとの通信」「共有パラメータウィジェットとのI2C/GPIO」を引き継ぐ通信担当で、1枚目とはUARTリンク1本(J9)のみで接続する。これにより1枚目の負荷を軽減する狙い。パズル用スロットはタイマーがスロットから外れて1枚目に統合されたため、6→5区画に減った。

## 現状の要約(2026-09-27)

- Board2(通信担当、無印Pico 2/RP2350、Wi-Fi不使用)は、**5区画**のパズルモジュールと **区画ごとのUART専用線(点対点)** で通信する。I2C共有バス(0x10〜0x20のアドレス方式)は廃止(ユーザー決定: ハード側で先に組み、ソフト担当に合わせてもらう)。
- U1のシンボル/footprintは`RPi_Pico:Pico`/`RPi_Pico:RPi_Pico_SMD_TH`のまま(差し替えなし。Value欄も旧`Pico 2 W`のまま残しているが、実装するのは無印Pico 2でよい。Pico 2とPico 2 Wはピン配置互換のため回路図上の違いはなく、Descriptionのみ実体を反映)。
- **電源方式が変わった**: Board2自身のUSB VBUS(pin40)はもう使わず`no_connect`。代わりにJ9(マスターリンク)経由でBoard1から受け取る5V(`VIN_5V`)がU1のVSYS(pin39)に入り、F1〜F5(区画ごとのポリスイッチ)の起点にもなる。
- J7(GP0/GP1、OLED用I2C)とJ8(GP2〜GP7、共有パラメータ用スイッチ/LED)は共有パラメータウィジェット向けの別枠コネクタで、モジュールスロットではない。
- J9(マスターリンク)はBoard1(タイマー/マスター基板)とのUART+電源リンクで、モジュールスロットではない。
- ホストはモジュール用パネルではないので、100mm/80mm角の配置案は不要(OSC2026確認済み)。

## 通信: J1〜J5(区画ごとのUART専用線、2026-09-27に5区画化)

- **2026-09-27: タイマーがスロットから外れてBoard1に統合されたため、6区画→5区画に減った(J6は廃止)**。
- **ロック仕様(全モジュール・ホスト共通、ハブ確定)**: JST XH 4極、ケーブルはストレート。モジュール側はPin1=GPIO0(UART0 TX、モジュール→ホスト)、Pin2=GPIO1(UART0 RX、ホスト→モジュール)、Pin3=VCC(5V)、Pin4=GND。ホスト側は区画ごとに **Pin1=ホストRX、Pin2=ホストTX**(ストレートケーブルで結ぶと自動的にTX↔RXのクロス接続になる)。
- ホスト側のネット名(ホスト視点): `Sn_RX` = Pin1 = ホストのRX、`Sn_TX` = Pin2 = ホストのTX(n=1〜5)。
- push-pull駆動(3Mbps級を狙うため。オープンドレイン+プルアップではRC時定数で出せない)。**プルアップは付けない**。3.3V論理。ボーレート・フレーミングはソフト担当が決める(ハードでは気にしない)。
- モジュール側の回路は変更不要(全モジュールの回路図で既にPin1=GPIO0、Pin2=GPIO1に配線済み)。GPIO0/1は通信専用で、モジュール周辺部品はGPIO2〜28から選ぶ。
- I2Cアドレスによる識別は廃止。区画ごとに配線が独立するので、バス上のアドレス衝突という概念自体がなくなった。モジュール種別の識別が必要ならソフト側のプロトコルで行う。
- Valueは `MODULE_SLOT_1`〜`MODULE_SLOT_5`、Descriptionは実配線と一致する文言(配線を終えてから書く。keypadはDescriptionが実配線と食い違っていた失敗例)。
- footprint: `Connector_JST:JST_XH_B4B-XH-A_1x04_P2.50mm_Vertical`(J1〜J5・J7・J9共通)。

## 専用I2Cリンク J7 と共有パラメータ J8(2026-09-16追加、今回変更なし)

### J7: OLED用I2C(JST XH 4極)
- GP0/GP1のI2C0を、ホストと共有パラメータ用OLED(SSD1315、0x3C)の1対1リンク専用として残した。ピン配置は従来のJ1〜J5と同じ Pin1=SDA / Pin2=SCL / Pin3=3.3V / Pin4=GND。
- **Pin3は3.3V(U1のレギュレータ出力)であり、モジュール用のVBUS由来5V(VCC_Jn)とは別系統**。ヒューズなし。
- Value `SHARED_WIDGET_I2C_TAP`。配置は J1〜J5 と同じ列(X=76.2、回転0)の続き `(76.2, 129.54)`。

### J8: 共有パラメータ用スイッチ/LED(JST XH 7極)
- Pin1=GND、Pin2〜7=SHARED_ODDEVEN / VOWEL / BATT2 / BATT3 / PORT / LED(GP2〜GP7、上表)。footprint `Connector_JST:JST_XH_B7B-XH-A_1x07_P2.50mm_Vertical`(OSC2026が `datasheet/xh.pdf` でB7B-XH-A・XHP-7・SXH-001T-P0.6の実在を確認済み)。Value `SHARED_WIDGET_GPIO`。配置 `(76.2, 154.94)`。
- スイッチ入力はホスト側に外付けプルアップを置かず、RP2350内蔵プルアップ(ファームで `PULL_UP`)を使う前提(keypadのボタンと同じ思想)。スイッチはGPIOとGNDの2点だけ。
- LED(GP7)の電流制限抵抗はウィジェット側基板に載せる。白色LED(OSW54K3131A、Vf typ3.1V/max3.6V)を3.3V駆動する件は、5V化せず抵抗100〜150Ωから実測調整し、明るい個体を選別する方針で決着済み(2026-09-17)。

### J9: マスターリンク(Board1とのUART+電源、2026-09-27追加)

- Board1(マスター/タイマー担当、無印Pico 2、タイマーモジュール筐体内に同居)との専用UARTリンク兼電源リンク。JST XH 4極。J1〜J8と同じ配置パターン(X=76.2、回転0)の続きに配置(`(76.2, 177.8)`)。
- ピン配置: Pin1=`M_RX`(このボードのRX、Board1のTXを受信)、Pin2=`M_TX`(このボードのTX、Board1のRXへ送信)、Pin3=`VIN_5V`(Board1からの電源IN。J1〜J5の`VCC_Jn`のような出力ではなく、**入力**である点に注意)、Pin4=GND。
- Pin1/Pin2は、GP18/GP19(旧J6用だったS6_TX/S6_RXの物理配線をそのまま流用し、ラベル名だけM_TX/M_RXに変更)につながる。
- Pin3の`VIN_5V`は、U1のVSYS(pin39)およびF1〜F5(区画ごとのポリスイッチ)の入力側と同一ネット。Board1側で保護(ポリスイッチ等)された5Vを受け取る前提で、Board2側にヒューズは入れていない。
- Value `MASTER_LINK`。footprintは他のJST XHコネクタと同じ`Connector_JST:JST_XH_B4B-XH-A_1x04_P2.50mm_Vertical`。
- モジュールスロットではない(J7・J8と同様)。

## プルアップ(R1/R2)

- R1(SDA-3.3V)・R2(SCL-3.3V)、各4.7kΩ、`Device:R`(footprintはkeypadのLED抵抗と同じTHT品を仮採用)。**役割はJ7のOLEDリンク専用**で、UARTの区画には無関係。
- 使用したOLEDモジュールは内蔵プルアップ付きで、外付けなしでも動作した(2026-09-24、ブレッドボードで実機確認)。基板側R1/R2は内蔵プルアップと並列になる。モジュール内蔵の抵抗値は未確認だが、一般的な4.7k〜10kなら合成は約2.4〜3.2kΩで、I2Cの下限(3.3V・3mAシンクで約1kΩ)を十分上回る。別のOLED/LCDモジュールに替わっても動くよう、R1/R2は残す(内蔵抵抗値を実測できれば、この計算を確定させる)。

## 電源分配

- **2026-09-27変更: 電源の起点がU1自身のVBUSではなく、J9経由でBoard1(マスター/タイマー基板)から受け取った`VIN_5V`になった。** U1のVSYS(pin39)が`VIN_5V`に接続され、U1自身もこの電源で動く。U1自身のVBUS(pin40)は`no_connect`(自分のUSBから給電する設計ではなくなったため)。
- `VIN_5V`ラベルから分岐し、5本にそれぞれポリスイッチF1〜F5(`Device:Polyfuse_Small`)を直列に入れ、各JSTのPin3(`VCC_J1`〜`VCC_J5`)へ。keypadが `power:+5V` を流用していたのは意味的に不正確なので踏襲しなかった(VIN_5VもJ9経由とはいえ実体は5V系統の生電源)。
- 設計思想: 通信線を区画ごとに独立(点対点)にしたのと同様、電源も分岐ごとに保護素子を入れて「1箇所の不良が他に波及しない」構成にした。
- **設計ルール(ハブ確定): パネルごとのピーク電流は200mA以内(LED輝度はファーム側で制限する前提)**。ポリスイッチは、この200mAに対してホールド電流に余裕を持たせる。当初の「ホールド約200mA」は余裕ゼロで不適切と判明し、**推奨をホールド0.3A(Bourns MF-RX030/72-0、秋月 通販コード113076、¥30)に変更(2026-09-24)**。比較の詳細は下の「ポリスイッチ選定」。全5本を同一仕様にする(どのスロットにどのモジュールが挿さるか固定しない設計方針のため、特定スロットだけ別容量にはしない)。footprintは未定(下記)。
- **前提と注意**:
  - 36連WS2812B案の迷路に限り、ピーク電流が `MAX_BRIGHTNESS=20`(ファーム)に依存する(全灯で約100mA、通常動作で約108mA。ファームで輝度上限を上げるとポリスイッチの再確認が必要)。迷路担当は位置表示をディスプレイ案(OLED/TFT、約80〜110mA)に変更する方向で、その場合この依存はなくなる見込み。表示器の最終決定はユーザー判断待ち(決まればOSC2026から連絡予定)。
  - ホールド電流は23℃基準で、高温ほど低下する(ピーク予算200mAとホールド200mAの同値では余裕ゼロ)。→ 上記のとおり0.3A級に変更。
  - USB電源はPCのUSBポート直結ではなく、5V/3A級の充電器を使う。根拠と電源入力方式の比較は下の「電源容量の見積もりと電源入力」。**2026-09-27時点の注記: 以下の節はBoard2が自身のUSBから給電していた旧構成(2026-09-24時点)の検討であり、USB入力そのものはBoard1(マスター/タイマー基板)側に移った。電流見積もり(パネル・ホストの消費電流)と保護素子の考え方(ポリスイッチ選定)は引き続き有効な参考値だが、「電源入力方式の比較」(案A/B/C)はBoard1の電源入力設計として読み替える必要があり、Board1側で未反映(要ユーザー確認)。**

## 電源容量の見積もりと電源入力(2026-09-24 検討、推奨案のみ・回路図は未変更。2026-09-27注記: USB入力点はBoard1に移動、詳細は直前の注記を参照)

### 5V側の負荷の見積もり

| 負荷 | 常用 | 最悪 | 根拠 |
|---|---|---|---|
| 6区画のパネル | 約0.7A | 1,200mA(200mA×6) | 最悪はハブ確定の「パネルごとのピーク≤200mA」。常用は例: ワイヤー系175mA×2(報告値)、迷路80〜110mA(報告値)、サイモン・タイマー各約100mA(仮置き)、キーパッド約50mA(仮置き)。**仮置きを含むので実測で確定させる** |
| ホスト(Pico 2 W) | 約40〜60mA | 100mA(設計値) | 実測例(電池電圧での測定): アイドル38mA、Wi-Fi接続60mA(省電力)/80mA(省電力なし)。Pico 2 Wデータシートには消費電流の数値が見当たらない(「VBUSとVSYSの電流は用途による」とのみ記載) |
| OLED+白色LED(3.3V側、Picoのレギュレータ経由) | 約20mA | 約30mA | 見込み値(OLEDは0.96インチで10〜20mA程度、LEDは数mA〜10mA)。要実測 |
| **合計** | **約0.8A** | **約1.4A** | |

- ウィジェットの表示器が案C(2.42インチOLED)の場合、ウィジェット設計メモ(Waveshare仕様)では全点灯約196mA/全消灯7.3mA(3.3V)。J7の3.3VはPicoの3V3(OUT)から取るので、外部負荷は全点灯の最悪で約206mA(白色LEDの数mA〜10mAを含む)。Picoの推奨(300mA未満)には収まるが、ハブの目安「半分以下(150mA)」は超える。文字表示のみの実消費電流は9/26着荷の現物で実測待ち。5V側では約160mA相当(変換効率85%と仮定)で、最悪合計は約1.4Aから約1.5Aに増える(上の表は0.96インチ想定の約30mA)。
- Bluetooth動作のPico 2 Wで基準約110〜120mA・ピーク約300mAという掲示板報告がある(Wi-Fi/BTを使うファームの場合の瞬間電流の目安。未検証)。瞬間電流は電源入口のバルクコンデンサで吸収する前提にする。
- 一般的なUSB規格の値: USB 2.0の標準ポート500mA、USB 3.xの標準ポート900mA、充電ポート(BC1.2)で最大1.5A。**常用0.8Aでも標準ポートを超える**ため、PCのUSBポートから給電するのは単体試験(ホスト+1〜2モジュール)に限る。全モジュールを挿した状態では、**5V/2A以上の充電器が必須**(最悪1.4Aを定格の70%以下に収める。推奨は5V/3A)。

### 推奨

1. **当面〜試作(ブレッドボード、初期のPCB)は案A**。条件: 5V/3A級の充電器、電源線が太い(24AWG級)短い(1m以下)microUSBケーブル、PCのUSBポートは使わない(単体試験を除く)。
2. **PCB化では案Bを基本に推奨**(案Aに切り替えられる半田ジャンパを付ける構成も可)。理由: 最悪1.4AをPicoの端子・内部配線に通す設計はRPiの保証外で、展示当日に落ちると致命的なため。構成案: 外部5V入力(2ピン)→逆接続保護(ショットキー等)→5Vレール(バルクコンデンサ)→F1〜F6→J1〜J6、5Vレール→ショットキー→VSYS。**構成が変わるので、ユーザー承認後に回路図へ反映する(未反映)**。
3. **判断の目安**: モジュールが揃った時点でUSB電流計により常用・最悪の電流を実測する。実測ピークが1.0A以下、かつホスト入口のVBUSが4.5V以上なら案Aで継続してよい。超えるなら案B。(1.0Aはデータシートに端子許容電流の規定が無いことに対する保守的な設計判断で、根拠の数値ではない。要議論)
4. **バルクコンデンサ**: 案A/Bとも、5Vレール入口に470µF以上(耐圧16V以上)を推奨(NeoPixelやWi-Fiの瞬間電流の吸収)。現回路図には未搭載。ハブ共通ルール(2026-09-27)の「モジュールのJST XH Pin3-Pin4付近に100µF/16V以上」は電源を受け取るモジュール側のルールで、電源を供給する側のホストのJ1〜J6には当てはまらない。ホストの470µFは、6モジュール分の100µF(計600µF)とは別に、レールの入口に置くもの。耐圧はハブ共通ルールに合わせて16V以上にした。

## ポリスイッチ選定(2026-09-24 検討)

- 用語: **ホールド電流(Ihold)** = 23℃で流し続けてもトリップしない最大電流。**トリップ電流(Itrip)** = 23℃でトリップが確実に起きる最小電流(約Iholdの2倍)。両者の間の電流では、トリップするかどうかが不定。どちらも温度が上がると低下する。トリップまでの時間は秒オーダーで、電子ヒューズのような即時遮断ではない(短絡中はレールが一時的に落ちうる)。

## GND

- U1の全GND系ピン(pin3,8,13,18,23,28,38,42、およびAGND=pin33)を漏れなく共有GNDネットへ。J1〜J9のGNDピンも同じネット。`power:GND`は消費点ごとに置く(keypad流)。
- ERC対策として `power:PWR_FLAG` をGND/+3.3V/`VIN_5V`に1個ずつ配置(KiCad 10では、`power:GND`/`+3.3V`シンボルがpower input型のため、電源出力(power output)型ピンが無いとpower_pin_not_drivenになる。keypadにも同じ不備があった)。**2026-09-27: 旧VBUSネット上にあったPWR_FLAG(#FLG03)は、電源の起点がVSYS(pin39)/`VIN_5V`に変わったのに合わせて、その位置(U1 pin39のすぐ隣)へ移設した。** 残る警告1件は「U1 pin38(RPi_Picoライブラリ側でBidirectional型と定義)とPWR_FLAGの pin_to_pin」で、ライブラリ由来の無害なもの。

## KiCad作業の落とし穴(過去に実害があったもの)

- 座標は1.27mm格子の整数倍。ワイヤーは2点のみ。ライブラリシンボルのピンのシート上の絶対座標は `(配置X+ローカルX, 配置Y−ローカルY)`(Yは引き算)。
- **ERCが通っても配線が正しい保証にはならない**。`kicad-cli sch export netlist` で各ネットのメンバーを部品・ピン名で確認する。今回はスクリプトでネット毎に期待メンバーと照合した。
- Picoのピン列の真上に無関係な部品のピンを置かない(2.54mm隣のピンへ誤接続してもERCは検出できない)。
- ラベルの向き: 左側のピンには `angle 180 / justify right`、右側のピンには `angle 0 / justify left` のラベルを置くと、テキストがシンボル本体に重ならない。
