# ボタンモジュール C案(単色LED+NPN駆動)机上準備(下書き、2026-09-27)

位置づけ: ユーザーの回答待ちの間の**机上の下書き**(ハブ了承済み、KiCad・発注は未着手のまま)。「シャッター」の意味や文言の出し方が決まれば変わる。BOMは `status_2026-09-27.md` §3(C1、Pico込み約¥2,250)が正本なので再掲しない。

前提: C1(面=単色10mm LED 4色から1灯、ストリップ=同4色から1灯、黒=全消灯)、文言=0.96インチOLED(I2C)。文言を「切り抜き窓+LED」に変える場合は、OLEDのGP2/GP3をLED×4(NPN)に置き換える。

## 1. GPIO割当(仮)

Pico物理ピン番号は `password_design_notes.md` §5と同じ並び。GPIO0/1はUART0(ホスト通信専用)で予約。

| 信号 | GPIO | 物理ピン | 方向 | 備考 |
|---|---|---:|---|---|
| UART0 TX(→ホスト) | GP0 | 1 | 出力 | JST XH Pin1、予約 |
| UART0 RX(←ホスト) | GP1 | 2 | 入力 | JST XH Pin2、予約 |
| OLED SDA(I2C1) | GP2 | 4 | 双方向 | SSD1315、0x3C、モジュール内蔵プルアップ |
| OLED SCL(I2C1) | GP3 | 5 | 出力 | 同上 |
| ボタン(タクト4個並列) | GP4 | 6 | 入力(内部プルアップ) | 押下でLow、もう一方はGND |
| 面LED 白 | GP5 | 7 | 出力(NPNベース) | 起動直後に出力Low |
| 面LED 青 | GP6 | 9 | 出力(NPNベース) | 同上 |
| 面LED 赤 | GP7 | 10 | 出力(NPNベース) | 同上 |
| 面LED 黄 | GP8 | 11 | 出力(NPNベース) | 同上 |
| ストリップ 白 | GP9 | 12 | 出力(NPNベース) | 同上 |
| ストリップ 青 | GP10 | 14 | 出力(NPNベース) | 同上 |
| ストリップ 赤 | GP11 | 15 | 出力(NPNベース) | 同上 |
| ストリップ 黄 | GP12 | 16 | 出力(NPNベース) | 同上 |
| 状態LED(緑) | GP15 | 20 | 出力 | GPIO直結+47Ω(他モジュールと同じ) |

- 使用14本(予約2含む)。空き: GP13、GP14、GP16〜22、GP26〜28。
- ハブ規則(RP2350-E9、2026-09-27にハブがデータシート原文で確認): 影響は**A2ステッピングのみ、A3以降は修正済み**。手元のPico 2のチップ刻印(A2/A3/A4)をまず確認する。A3/A4なら追加のプルダウンは不要で、通常のソフト規則(LED駆動ピンは起動直後に出力Lowにし、入力モードにしない)だけで足りる。A2の個体が混ざる可能性がある、またはソフト規則を守れない場合のみ、NPNのベース-GND間に8.2kΩ以下(4.7kΩ)を追加する。
- 面LEDとストリップLEDは、それぞれ**同時に1灯だけ点灯**する制御(ファーム側)。全点灯は約250mAで予算超過。
- 5V入力(JST XH Pin3-Pin4付近)に**100µF/16V以上の電解コンデンサ**を1個(2026-09-27、全モジュール共通ルール)。
- OLEDは3.3V系統(Picoの3V3(OUT))から給電する想定。3V3(OUT)は合計300mA未満推奨(半分以下が望ましい、2026-09-27ハブ確認)だが、OLEDは数mA〜21mA程度なので余裕は大きい。

## 2. 回路ブロック(1チャンネル分)

```
5V ──[R]──►|LED|── NPN(2SC1815) コレクタ
                     エミッタ ── GND
GPIO ──[1kΩ]── ベース      (必要ならベース─GND間に4.7kΩ)
```

| LED | 目標電流 | 抵抗(初期値、5V・Vce(sat) 0.1V) | 備考 |
|---|---:|---:|---|
| 赤・黄(Vf 2.1V) | 20mA | 150Ω | Vf最大2.6Vで約15mA |
| 白・青(Vf 約3.1V) | 20mA | 91Ω | 5Vがポリスイッチ・ハーネスで0.2〜0.4V下がり、電流が10〜25%変わる→**実測で調整** |
| 面の白(明るさ優先) | 最大30mA | 62Ω | 10mm白のみ(5mm白は20mA以下) |

- 2SC1815のピン順はE-C-B(UTCデータシート)。他のTO-92は別に確認。
- 5V入力に100µF以上のバルクコンデンサ(ハブ前提)。
- タクト: 4足のうち同じ辺の2本が常時導通、向かい合う辺から1本ずつ使う(キーパッドの知見)。ドーム縁の4点は、GPIO側とGND側を並列にまとめる。

## 3. ブリングアップ手順(下書き)

テスト用スクリプト(MicroPython)は、ピン割当と文言の出し方が確定してから書く(`password_bringup_test.py` と同じ形式を踏襲する予定)。

| # | 確認 | 方法 | 合格の目安 | 記録欄 |
|---|---|---|---|---|
| 0 | 通電前 | 5V-GND間の導通(短絡)なし、NPNのピン順、LEDの向き | 短絡なし | |
| 1 | 状態LED | 点滅させ、47Ω両端の電圧を測る(電流=電圧÷47) | 点灯、電流を記録(ハブ連絡事項の依頼) | |
| 2 | 起動時のLED | 電源投入〜main開始の間に、面・ストリップLEDが点かないか目視。あわせてPico 2のチップ刻印(A2/A3/A4)を記録 | 点かない(E9対策。A3/A4ならそもそも対象外) | |
| 3 | OLED | `i2c.scan()`で0x3Cが出る、文字表示 | 0x3C検出、4語(中止/起爆/長押し/押す)の表示 | |
| 4 | タクト | GP4の押下でREPLに表示、押している間ストリップ点灯 | 4点のどれを押しても検出 | |
| 5 | LED各色 | 1灯ずつ点灯し、USBメーター(または抵抗両端の電圧)で電流を測る | 目標電流±20%、色が判別できる | |
| 6 | 全体電流(平均) | 面1灯+ストリップ1灯+OLED表示の状態をUSBパワーメーターで測る | 200mA以内(目標120mA以下) | |
| 7 | 温度 | 数分点灯後に再測定、Vf低下による電流増を確認 | 電流の増加が許容内 | |
| 8 | 色の見え方 | 半透明キャップ試作を被せて、青/赤/白/黄/黒(消灯)を並べて見る。明るい部屋で白と黄、ストリップ4色を判別できるか | 5色を判別できる | |
| 9 | UART(任意) | GP0とGP1を短絡して送受信 | 送った文字が受信できる | |

## 4. ユーザーの回答で変わるもの

- **文言の出し方**(ハブから、ボタン側から直接聞いてよいとの回答済み): OLEDのままなら上記のとおり。切り抜き窓+LEDなら、GP2/GP3が不要になり、代わりに文言LED×4(NPN)が入る。
- 「シャッター」の意味(A/B/C): Aならサーボ(PWM+電源遮断MOSFET)が、Bなら液晶(GPIO2本)が追加される(設計メモ§6)。

## 5. KiCad着手時に守る共通ルール(2026-09-27時点、着手前の備忘)

- ERCは0件に揃える(未使用ピンはno_connect、電源ネットはPWR_FLAG)。**許容されるのは`U1 pin38のpin_to_pin警告`1件のみ**(RPi_Picoライブラリ由来、既知・許容として設計メモに明記する)。
- PWR_FLAGの記号名は「power:PWR_FLAG」(lib_symbolsキャッシュの名前が違うと効かない)。
- ピン・ワイヤーの端が別ネットの配線の「途中」に乗らないよう、座標で確認する(Passwordで実害あり)。
- 座標は1.27mm格子の整数倍。ワイヤーは2点のみ。ライブラリシンボルのピンの絶対座標は(配置X+ローカルX, 配置Y−ローカルY)でYは引き算。
- ERC通過後も`kicad-cli sch export netlist`で目視確認する。
- ドーム径・押下機構(タクト4点の位置)。
